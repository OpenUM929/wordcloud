 서버 프로세스가 죽으면 배치 스레드도 함께 죽지만, DB의 status='running'은 아무도 바꿔주지 않습니다. "스위치는 ON이지만 전등은
  꺼져있는" 비유가 정확합니다.

  ---
  파일의 해결책 ("24시간 전 running →failed") 은 불필요하게 복잡합니다

  핵심 관찰: Flask 서버가 기동 중이라면, 이전 프로세스의 스레드는 전부 죽었습니다. 따라서:

  ▎ 서버가 막 시작됐을 때 status='running'인 배치는 전부 죽어있다 — 시간 조건이 필요 없습니다.

  _init_db()는 서버 기동 시 호출됩니다. 거기에 한 줄 추가하면 됩니다.

  ---
  그런데 failed로 바꾸면 UX가 부정확합니다

  현재 상태값: running | completed | failed

  ┌────────────────────┬───────────────────────┬────────────────────────────┐
  │        상황        │       실제 원인       │        적합한 상태         │
  ├────────────────────┼───────────────────────┼────────────────────────────┤
  │ 서버 재시작/Ctrl+C │ 정상 종료, 재개 가능  │ ✅ "중단됨" (Resume 가능)  │
  ├────────────────────┼───────────────────────┼────────────────────────────┤
  │ 처리 중 예외 발생  │ 코드 버그/데이터 오류 │ ⚠️"실패" (원인 확인 필요) │
  └────────────────────┴───────────────────────┴────────────────────────────┘

  둘 다 failed로 표시하면 "정상적인 서버 재시작"과 "실제 오류"를 구분할 수 없습니다. interrupted 상태를 추가하는 게 맞습니다.

  ---
  권장 수정 방향

  ①DB 스키마에 interrupted 추가
  -- running | completed | failed | interrupted

  ②_init_db() (기동 시 1회)에서 일괄 전환
  conn.execute("""
      UPDATE batch_work_orders
      SET status     = 'interrupted',
          updated_at = datetime('now','localtime')
      WHERE status = 'running'
  """)

  ③프론트엔드 표시 분리

  ┌─────────────┬────────────────────────────┬─────────────────────────┐
  │   status    │            표시            │       Resume 버튼       │
  ├─────────────┼────────────────────────────┼─────────────────────────┤
  │ running     │ 처리 중 (서버 살아있을 때) │ 미표시                  │
  ├─────────────┼────────────────────────────┼─────────────────────────┤
  │ interrupted │ ⏸중단됨 (서버 재시작)     │ 표시                    │
  ├─────────────┼────────────────────────────┼─────────────────────────┤
  │ failed      │ ❌ 오류 발생               │ 표시 (주의 문구와 함께) │
  ├─────────────┼────────────────────────────┼─────────────────────────┤
  │ completed   │ ✅ 완료                    │ 미표시                  │
  └─────────────┴────────────────────────────┴─────────────────────────┘

  ④get_latest_incomplete_work_order()도 갱신
  WHERE status IN ('interrupted', 'failed')
