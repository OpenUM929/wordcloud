# 오분류 패턴 발굴 — 24년 장점/단점 코퍼스 (260624)

> 입력: `data/24년 장점.csv`(batch_20260624_1, 444,080) + `data/24년_단점.csv`(batch_20260624_0, 427,287).
> 방법: `dataset_pipeline.py`(규칙 적용·절분리·약지도·PII게이트) → `weak_export_260624.jsonl` 889,465 레코드.
> 위 자동 마이닝(`pattern_mining_260624.md`)에 더해, **필드(장점/단점)를 극성 정답신호로 써서 필드×우리판정 교차**를 산출하고 **직접 재판정**(사전라벨 불신 원칙).
> ⚠️ 후보 발굴까지만 — 어휘집/규칙 반영은 사람 additive append + 회귀(긍↔부 0) 통과 후에만.

## 1. 필드 × 우리규칙 최종판정 (문장 레코드)

| 필드 | 총 | positive | negative | neutral |
|------|----|----------|----------|---------|
| 장점 | 443,637 | 423,926 (95.6%) | 8,794 (2.0%) | 10,917 (2.5%) |
| 단점 | 426,730 | **131,566 (30.8%)** | 138,223 (32.4%) | 156,941 (36.8%) |

- 단점 필드의 **30.8%가 여전히 positive** 판정. KoTE 원본(31.4%)에서 우리 규칙이 거의 못 줄임(133,960→131,566).
- **사용자 지적("단점이 장점으로")이 데이터로 확인됨.** 반대(장점→negative)도 2.0% 존재.

## 2. 직접 재판정 — 두 종류가 섞임

단점필드→positive 표본 50건을 직접 판정한 결과:

- **우리 오류 아님 (필드만 불일치)**: 리뷰어가 단점 칸에 칭찬을 적음. 내용이 진짜 긍정 → 우리 positive 판정이 **맞음**. (예: "열정·책임감·전문성 두루 갖춤", "탁월한 업무해결능력의 베테랑"). → 손대면 안 됨.
- **진짜 부→긍 오분류 (교정 대상)**: 단점 맥락의 **개선요청/필요 표현**이 긍정으로 샘. (예: "서로존중하는 동료관계 형성 필요", "건강에 더 신경써 주십시요", "소통 및 조정능력 보완", "너무 사무적이다").

## 3. 지배 패턴 — 단점 맥락 개선요청 (부→긍)

- 단점필드 positive 131,566건 중 **개선요청 표지**(필요·보완·바람·바랍·주십·좋겠·좋을·요망·당부·했으면·개선…) 포함 **38,656건**.
- 트랩 제외(결핍의 부정 = 실제 긍정: "보완점 없음"·"부족함이 없다"·"지금처럼 유지하면 좋겠" 8,043) → **정제 부→긍 강후보 30,613건**.

### 🔴 핵심 구멍 — 기존 가드가 구조적으로 못 보는 경로

부→긍 강후보 30,613건의 applied_rule 분포:

| applied_rule | 건수 | 의미 |
|---|---|---|
| **rule4_default** | **24,019 (78%)** | KoTE가 직접 긍정 점수 → **어떤 override도 미발동** |
| positive_rescue | 5,341 | override가 긍정으로 끌어올림 |
| rule2_contrast_lasthigh | 1,085 | 끝절 고긍정으로 판정 |
| rule1_contrast_lastlow | 164 | |
| negation_praise | 4 | |

- 기존 개선요청 가드(`has_constructive_need`·`has_improvement_request`)는 **`positive_rescue` 경로 전용**. → positive_rescue 5,341만 사정권, **KoTE 직접 긍정(rule4_default) 24,019건(78%)을 구조적으로 못 본다.**
- 즉 "단점이 장점으로" 잔존의 주범은 override 버그가 아니라 **KoTE 자체가 개선요청을 긍정으로 점수 + 무보정 통과**.

## 4. 반대 방향 — 장점필드→negative (긍→부, 위험방향)

- 8,794건. 다수는 리뷰어가 장점 칸에 단점/무응답을 적음(내용 negative → 우리 판정 맞음).
- 진짜 긍→부 오분류는 **짧은 긍정 트레이트 명사구**가 KoTE에서 부정 점수 + rule4_default 통과: "공평성, 업무능력, 리더십" / "업무열의가 많다" / "적극적인 업무태도" / "명확한 의사전달" / "감정기복이 적습니다" / "직원들을 이해하려는 성향이 강함".
- ⚠️ **정직한 한계**: 자동 카운트(부정신호 없는 행 3,737)는 노이즈 큼 — `비-`접두 부정("비전문성")·"안됨" 등 진짜 부정이 다수 섞여 과대치. 진짜 긍→부는 그보다 적으나 **존재 확인**. 규모 확정은 표본 gold 필요(rule4_default 짧은 명사구 군집).

## 5. 제안 (권고 — 사용자 승인 후 additive 구현 + 회귀)

1. **개선요청 게이트를 positive_rescue 전용에서 전 경로(특히 rule4_default)로 승격** — 개선요청 표지 ∧ 트랩 없음 → **neutral 강등**(negative 아님). neutral 타깃이면 긍↔부 위반 회피(핵심가치: 중립↔양방향 비위반), 긍→부 신규오류 위험 0.
   - 트랩 필수 보존: 결핍의 부정("보완점 없음"·"부족함이 없다"), "지금처럼/그대로 유지", "관행을 개선하려는 의지"(개선=긍정 자질), "어려움 극복".
2. **긍→부(짧은 긍정 트레이트)**: 즉시 규칙화 금지. rule4_default 부정 명사구를 표본 gold로 모아 군집 후 표지 승격(추측 금지). 검증셋에 held-out 적재.

> ⚠️ 1번은 production `perspective_service`/`hr_context_lexicon` 변경으로 ~24K 행 판정이 바뀜(되돌리긴 쉬우나 영향 큼) → §0 역할 규약대로 **권고로 올리고 승인 후 구현**. 구현 시 회귀 7종 + 장점 적대검증(긍→부 0) + 단점 적대검증(부→긍 감소) 동반.
