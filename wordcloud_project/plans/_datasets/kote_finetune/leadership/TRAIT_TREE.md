## 1. 목적

리더십을 KoTE 44 감정에 평면으로 더하지 않고 **자기 다계층 라벨 공간**으로 둔다. 현재 코드의 6역량은 거친 1층뿐, 레퍼런스(외부 레포 OpenUM929/leadership 정본 `data/traits`: **trait20(긍·균형14+리스크6) / micro125(trait 참조본; 개별 178 공존) / macro80(Pos48+Neg32) / 이론 카테고리8**, AGENTS v2.1·commit `49b261c`, 2026-06-19 검증 스냅샷)는 **골격 참고용**. trait별 결정 micro label 검증본·상세 스냅샷은 [`trait_library_ref.md`](trait_library_ref.md).

**두 가지 용도(둘 다 같은 트리·같은 게이트 사용)**:
- **A. 데이터셋 라벨 공간**: 문장에 리더십 trait gold 부여(KoTE 파인튜닝 보조).
- **B. 사람(리더) 유형 타이핑**: 한 평가 대상의 문장 증거를 집계해 **리더십 종류를 프로파일로 구분**(§4-T). ← 이 다운스트림 목적이 아래 비교가능성 제약의 근거.

**설계 요구**:
1. 데이터셋 누적하며 trait 부여.
2. **세부 trait 문장이 부족하면 버리지 않고 부모 대그룹(=자식들의 합집합)으로 묶어** 사용.
3. 데이터가 쌓이면 세부로 **split(세분화)** — **트리 구조**.
4. 용도 B 때문에 **상위 축은 안정 고정**, 시간 축 연산은 **split-only**(§4 비교가능성).

→ binary(채택/보류) 대신 **"지원되는 가장 깊은 레벨에 라벨이 존재"** 하는, **백본 고정 · split-only 단조 세분화 트리**.

## 3. 트리 구조 (안정 백본 + 합집합 대그룹)

**2개 안정 백본 = 극성 축**(positive / risk) — 절대 재편 안 함, 비교 프레임의 뿌리.
그 아래 **대그룹 9개**는 *고정 카테고리가 아니라* **현재 데이터로 자른 절단선** — 즉 자식 세부 trait들이 아직 못 쪼개져 묶여 있는 **합집합(union)**이다. 데이터가 차면 합집합이 split되어 자식이 독립한다.

표기 규약: 대그룹 이름은 **멤버의 합집합**임을 드러낸다(예: `관계·소통` = `{관계, 소통}`). 자식이 게이트를 넘어 독립하면 그 자식이 새 노드가 되고, 대그룹은 *남은 멤버의 합집합*으로 의미가 줄어든다.

> 세부 trait 옆 `(Txxx)`는 외부 골격 레퍼런스(정본 20-trait)의 **trait_id 가설 앵커**다(각 trait의 결정 micro label 검증본은 [`trait_library_ref.md`](trait_library_ref.md) §3). 앵커는 군집 대조용 참고일 뿐 active 승격 권한이 없다 — 승격은 §4 게이트 통과 시에만. 현 세부 = **긍정·균형 14 + 리스크 6 = 20**.

### 긍정·균형 (백본: positive) — 14
| 대그룹 (현 절단 = 합집합) | 자식 세부 trait(잠재) · 외부 앵커 | 현 6역량 매핑 |
|---|---|---|
| 관계·소통 = {관계, 소통} | 협업형(T02) · 코칭형(T07) · 감정지능형(T08) · 공감형(T11) | 커뮤니케이션 / 팀워크 |
| 방향·전략 = {방향, 전략} | 비전제시형(T09) · 결단형(T01) · 분석형(T05) | 리더십 |
| 실행·성과 = {실행, 성과} | 실행형(T06) · 위기대응형(T04) · 전략실행형(T10) | 문제해결 |
| 혁신·학습 = {혁신, 학습} | 혁신형(T03) · 학습민첩형(T14) | 혁신 |
| 윤리·신뢰 = {윤리, 신뢰} | 윤리적용기형(T13) · 균형형(T12) | 윤리 |

> ⚠️ 군집 분리 검증 주의(micro 겹침): **공감형(T11)↔감정지능형(T08)**, **전략실행형(T10)↔결단형(T01)/실행형(T06)**. seed 겹침이 커 둘의 독립 active 승격은 군집 근거 확실할 때만.

### 리스크 (백본: risk) — 6
| 대그룹 (현 절단 = 합집합) | 자식 세부 trait(잠재) · 외부 앵커 |
|---|---|
| 권위·통제 = {권위, 통제} | 권위주의(T102) · 기복(과잉통제)형(T106) |
| 회피·무책임 = {회피, 무책임} | 회피형(T101) |
| 자기중심·조작 = {자기중심, 조작} | 자기애적(T104) · 조작적(T105) |

> 트리는 **아래로만 확장**: 절단선은 데이터가 차는 만큼 깊어진다(L1→L2→L3 micro). 노드 스키마는 임의 깊이 허용(§5). **위로 재병합·가지 가로지르기 금지**(§4 단조성).

## 4. rollup / split 메커니즘 (핵심) — split-only 단조

### 4-A. 문장 라벨링 (데이터셋 용도 A)
```
  1) 가장 깊은 세부 trait 매핑 시도(표지/군집 근거)
  2) 그 세부가 충분성 게이트 통과? (distinct 문장 ≥ N  AND  distinct 직원(src_hash) ≥ M)
       예   → 세부에 gold 부여                 [leadership_status = active]
       아니오 → 부모 대그룹(=합집합)에 귀속      [leadership_status = grouped]  ← 데이터 보존, 버리지 않음
  3) 코퍼스 성장으로 세부가 나중에 게이트 통과 → split(합집합에서 독립) [grouped → active]
```

### 4-B. 비교가능성 제약 (용도 B 때문에 필수)
- **시간 축 연산은 split뿐**. "merge"는 미래 동작이 아니라 *아직 안 쪼개진 초기 거친 상태*일 뿐.
- **금지**: 이미 쪼갠 자식을 다시 합치기, trait를 다른 부모로 옮기기, 가지를 가로질러 재군집 → 조상 관계가 깨져 **과거↔현재 유형 비교 불가**가 되므로.
- **허용**: 부모→자식 split(조상 관계 보존). 과거 `관계·소통`이던 대상은 split 후에도 그 우산 *아래* `관계` 또는 `소통` → 여전히 비교 가능.
- 백본(positive/risk)과 대그룹 경계 변경은 **버전 올린 택소노미 변경**으로만(변경 이력 + version bump). 군집은 *split 근거를 대는 증거*일 뿐, 트리를 통째로 다시 그릴 권한 없음.

### 4-T. 사람(리더) 단위 유형 타이핑 (용도 B — 같은 게이트 재사용)
```
  대상자의 문장 trait 라벨 집계:
    1) 극성 축별·대그룹별 빈도/강도 → 프로파일 벡터(단일 라벨 아님, 사람은 혼합형)
    2) 각 축에서 그 대상자의 증거가 세부까지 받쳐주면 → 세부로 타이핑(예: 코칭형)
                                  얕으면        → 대그룹으로만 타이핑(폴백, 예: 관계·소통)
    3) "리더십 종류" = 가장 강한 축 + 받쳐주는 깊이 (+ 부차 축)
```
- 문장 게이트(§4-A)와 **동일 로직을 사람 단위로** 한 번 더 적용 — 새 메커니즘 불필요.

### 공통 불변식
- **데이터 손실 0**: 희소 세부도 합집합 대그룹에 흡수되어 학습/타이핑에 계속 기여.
- **단조성**: 트리는 아래로 자랄 뿐 위로 무너지지 않음(split은 비가역 기록, 정정은 리비전 행).
- **직원 수 게이트(M)**: 1인 반복 표현 착시 방지 — `src_hash` 그룹 distinct(RUNBOOK/0617_05 §14-1 동일 키).
- **핵심가치 보존**: 문장·사람 양쪽 집계 모두 `leadership_polarity` 게이트 경유 → **긍↔부(=positive↔risk) 오분류 0**. negation 칭찬(`강압적이지 않음`)은 `is_negation_praise`로 리스크 오귀속 차단.

## 5. 스키마 (additive)

### 5-1. `leadership.jsonl` gold 행 (추가 필드)
```json
{
  "id": "ld-000123",
  "text": "방향을 명확히 제시하고 결정을 미루지 않음",
  "leadership_path": ["positive", "방향·전략", "결단형"], // 현재 절단의 스냅샷. 세부 미활성 시 ["positive","방향·전략"]
  "leadership_node": "T_DECISIVE",                     // 안정 노드 id(이름이 바뀌어도 불변) — 비교 기준
  "leadership_level": 2,                               // 1=대그룹 / 2=세부 (임의 깊이 허용)
  "leadership_status": "active",                       // active | grouped
  "leadership_polarity": "positive",                  // positive | risk (백본, 불변)
  "evidence_markers": ["방향제시", "결단"],
  "src_hash": "…", "review_status": "confirmed", "annotator": "rev01"
}
```
- `leadership_path`는 *현재 절단*의 스냅샷이라 split 시 길어질 수 있다. **비교의 기준은 안정 `leadership_node` id와 그 조상 경로**(split-only라 과거 노드는 항상 현재 경로의 조상). path 텍스트가 아니라 id 조상관계로 매칭.

### 5-3. 사람(리더) 유형 레코드 (용도 B, 파생 — append-only 산출물)
```json
{
  "subject_hash": "…",                                // 평가 대상(리더) 그룹키
  "as_of": "2026-06-18", "tree_version": 2,
  "profile": [{"node": "G_REL", "level": 1, "weight": 0.41, "status": "grouped"},
              {"node": "T_DECISIVE", "level": 2, "weight": 0.28, "status": "active"}],
  "dominant_type": "방향·전략(결단형)", "polarity_mix": {"positive": 0.86, "risk": 0.14},
  "evidence_count": 17
}
```
- 문장 gold에서 집계(§4-T). `tree_version` 고정으로 **버전 간 비교는 동일 버전끼리**. 파생물이므로 정식 gold 스트림과 분리(`../result/` 또는 별 파일).

### 5-2. 트리 정의 설정 파일 (신규, 코드 아님 — **가설**, 데이터로 관리)
`leadership/trait_tree.json` (본 폴더) — ⚠️ 이 파일은 **분류기가 아니라 가설 스캐폴드**다. seed_markers는 약한 prior일 뿐, 실제 trait는 §6 군집이 확정·수정한다.
```json
{
  "version": 1,
  "thresholds": {"min_sentences": null, "min_employees": null},  // 프로토타입 후 확정
  "nodes": [
    {"id": "B_POS", "level": 0, "name": "positive", "polarity": "positive", "parent": null, "backbone": true},
    {"id": "B_RISK", "level": 0, "name": "risk", "polarity": "risk", "parent": null, "backbone": true},
    {"id": "G_REL", "level": 1, "name": "관계·소통", "polarity": "positive", "parent": "B_POS",
     "members": ["관계","소통"], "seed_markers": ["소통","경청","배려","협력"]},
    {"id": "T_COLLAB", "level": 2, "name": "협업형", "polarity": "positive", "parent": "G_REL",
     "seed_markers": ["협업","협력","함께","팀워크"]},
    {"id": "T_COACH", "level": 2, "name": "코칭형", "polarity": "positive", "parent": "G_REL",
     "seed_markers": ["코칭","성장지원","피드백","육성"]}
    // … 백본 2 + 대그룹 9 + 세부 20 (전체 §3 트리)
  ]
}
```
- `id`는 **불변 안정키**(이름·절단 바뀌어도 고정) → 비교·집계 기준. `parent`는 split-only(부모 변경 금지). `members`는 합집합 대그룹이 품은 잠재 자식 표시.
- 트리/임계값을 설정으로 분리 → 확장·세분화 시 코드 변경 불요(additive).

## 6. 발굴 조사 절차 — **분석(군집) 우선, 추측 분류 금지**

> 🧭 **외부 자료 활용 전략은 [`trait_library_ref.md`](trait_library_ref.md) §0 참조** — 스키마(라벨 체계·패턴·표지)는 흡수(코드북·약지도 LF·군집 가설·부정표지 마이닝), 그들 샘플·라벨은 gold 비흡수. 미래 리더십 전용 모델 시드 가능성도 §0-4에 기록.

> 🔴 **불변 원칙(가장 중요)**: trait 분류는 **데이터 군집 분석으로만** 결정한다. seed_markers·트리는 **분류기가 아니라 검증 대상 "가설"**이다.
> - **순서는 입력 → 분석(군집) → 분류.** 군집 분석은 **생략 불가**. 데이터 없이 추측으로 trait를 붙이지 않는다.
> - **트리가 데이터에 굴복한다**: 군집 결과가 가설과 다르면 트리(대그룹·세부·이름)를 데이터에 맞춰 수정한다(merge/split/개명). 그 반대 아님.
> - **seed_markers의 역할은 단 하나** — "이 문장이 리더십 관련인가"를 거르는 **약한 prior**. trait 경계를 정할 권한 없음(경계는 군집이 정함).
> - 새 모델 불필요(기존 KoTE + 표지 피처로 무지도 군집).

| 단계 | 작업 | 비고 |
|------|------|------|
| 1. 리더십 문장 식별 | 6역량 키워드 + `hr_context_lexicon` 표지 보유 문장 → **밀도** (약한 prior, 분류 아님) | 밀도 낮으면 마이닝 시기상조 |
| 2. **무지도 군집(주 분석)** | KoTE 신호(`top_3`/필요 시 44-vec) + 표지 피처로 **군집** → *우리 코퍼스에 실제 존재하는* 자연 군집 발견 | **여기가 분류의 근거. 생략 불가** |
| 3. 가설↔군집 대조 | 발견된 군집을 §3 트리(가설)에 정렬 → 일치/불일치 판정, 트리 **수정**(merge/split/개명/신규) | 트리를 데이터로 교정 |
| 4. 게이트 적용 | 교정된 트리에 §4 규칙으로 active/grouped 판정 | 임계값 §7 |
| 5. 발굴 리포트 | 군집 × trait × 빈도 × 직원수 × 예문 × 판정 → `../result/` | 채택은 20보다 적/많을 수 있음(정직) |
| 6. (검토) gold 확정 | 리포트 표본을 사람이 검증 → `leadership.jsonl` confirmed | 추측 라벨은 학습 금지 |

- 제약: dev **CSV·KoTE만**(배치 불가), **서버 무단 실행 금지**, O(n)(수만 라인=KoTE 1패스, GPU `0617_07`), 가명화/내부망 전용.
- **데이터 현황(2026-06-18)**: 진짜 인사 코퍼스 **미반입**(원료 0). dev 보유 ~1.2k(`data/acquired_sentences_20260617.csv` 475 + `data/new_260617.csv` 722)는 **샘플**일 뿐 → 스크립트 동작 확인용 프로토타입만 가능. **trait 채택·gold 확정은 진짜 데이터 반입·군집 후에만.**

## 6-A. 누적·강화 사이클 (데이터가 들어올 때마다 / 매년 다면평가)

> 본 택소노미는 **일회성이 아니라 누적형**이다. 매년 새 다면평가가 들어오면 **다시 군집을 돌려 트리를 더 깊게(세분화) 강화**한다. RUNBOOK §2(상시 절차)와 한 몸.

```
[해마다 반복]  새 데이터 반입(일괄 이동 → acquired_sentences)
   → 누적 코퍼스(과거+신규) 전체로 §6 군집 재실행
   → 게이트 재평가: 전엔 grouped였던 세부가 이제 충분 → split(승격), 트리 한 단계 깊어짐
   → 신규 자연 군집 발견 시 → 가설에 없던 trait/대그룹 후보 추가(코퍼스 근거 有일 때만)
   → leadership.jsonl append-only 누적 + tree_version 올림(과거 gold 불변, 정정은 리비전 행)
```

- **단조 강화**: split-only(§4-B)라 트리는 해마다 **아래로만** 자란다 → 과거 분류와 **비교 가능**한 채로 정밀도만 상승.
- **append-only 누적**: 기존 gold·과거 연도 데이터 수정/삭제 없음. 새 데이터는 **추가**되어 게이트를 다시 넘게 함. → `acquired_sentences`·`leadership.jsonl` 모두 누적 설계(RUNBOOK §2-4, README append-only).
- **버전 경계**: 트리가 깊어지면 `trait_tree.json.version`·gold의 `tree_version`을 올린다. 유형 비교(§5-3)는 **동일 version끼리**, 교차 비교는 **조상 노드 id**로(split-only라 항상 정렬됨).
- **강화 대상**: 데이터가 쌓일수록 ① 세부 trait 해상도 ② 게이트 임계값 정밀도(§7) ③ (충분 시) KoTE 파인튜닝 보조 헤드(0617_05 P6)가 함께 강해진다.
- **연 1회 이상**: 다면평가 도착마다 트리거(RUNBOOK §1). "완료" 없음 — 데이터가 늘면 무한 반복.

## 7. 충분성 게이트 / 임계값

- 게이트: `distinct 문장 ≥ N` **AND** `distinct 직원(src_hash) ≥ M`.
- **N·M은 프로토타입 분포 확인 후 확정**(추측 금지). 잠정 가설 N≈30, M≈10 — 확정값은 `trait_tree.json.thresholds`에 기록.
