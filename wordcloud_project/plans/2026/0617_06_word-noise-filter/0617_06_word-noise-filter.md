## 2. 현재 동작 실측 (Kiwi 직접 실행 — 추측 아님)

`kiwipiepy.Kiwi().tokenize()` 실제 실행 결과:

```
'성실성실성실성실'
  성실 NNG start=0 len=2
  성실 NNG start=2 len=2
  성실 NNG start=4 len=2
  성실 NNG start=6 len=2

'ㄻ아ㅣ너림넝'
  ㄻ    SW  start=0 len=1   score=-4.496
  아    NNP start=1 len=1   score=-11.734
  ㅣ    SW  start=2 len=1   score=-2.557
  너림넝 NNP start=3 len=3   score=-33.376  (per-char ≈ -11.1)

(대조 — 정상 문장)
'성실하게 업무를 수행함'  → 성실/NNG, 하/XSA, 게/EC, 업무/NNG, 를/JKO, 수행/NNG, 하/XSV, ᆷ/EF
  성실 score=-10.849(per-char -5.4), 업무 -6.963(-3.5), 수행 -2.181(-1.1)

(대조 — 무의미 음절 추가 샘플)
'에테에타하라조 같은 헛소리' → 에테에타하라조/NNG score=-44.812 (per-char -6.4, 7음절)
'갑자기 외계인이 침공함'   → 외계인/NNG score=-10.706 (per-char -3.6, 정상 고유어)
```

**확인된 사실**:
- (a) `성실성실성실성실`은 Kiwi가 **단어 자체는 깨뜨리지 않고** "성실" 4개 토큰으로 정확히 분할한다. 문제는 분할이 아니라, 이 4개가 그대로 `word_frequency` 카운트에 **+4**로 들어가는 것이다(아래 §3-1).
- (b) `ㄻ아ㅣ너림넝`의 `ㄻ`, `ㅣ`, `아`는 길이 1 필터(`len(word) > 1`, `nlp_analysis.py:175`)로 우연히 제외되지만, `너림넝`은 Kiwi가 **고유명사(NNP)로 오태깅**하여 길이 3이라 필터를 통과 — 그대로 워드클라우드에 노출된다(아래 §3-2).
- (c) Kiwi Token 객체는 `score`(언어모델 로그스코어) 필드를 제공하며, gibberish 토큰의 음절당 점수가 정상 단어보다 뚜렷이 낮다(음수가 더 큼) — 단, 정상 희귀 형태소(예: 접두사 `헛` score=-9.788/1음절)와 경계가 모호한 사례도 있어 **임의 임계값을 지금 정하면 추측이 된다**. §6에서 코퍼스 기반 보정 절차로 분리한다.

### 3-1. 반복 도배가 빈도를 부풀림

- `nlp_analysis.py:119-134` `analyze()` — 위 결과를 그대로 `meaningful_words`에 저장.
- 소비처(전부 정제 없이 그대로 `Counter()`에 집계):
  - `metadata_analysis.py:68-87, 116` — 평가자별 `meaningful_words`를 그룹 전체에 `extend()` 후 `Counter(all_nlp_words)`. **한 평가자의 도배가 그룹 전체 단어 빈도를 직접 왜곡**.
  - `api_routes.py:110-120` — 단일 문서 `Counter(meaningful_words)`.
  - `wordcloud_service.py:277-284`, `wordcloud_data_service.py:59-71`, `batch_processor.py:116-125` — 동일 패턴.

### 3-2. Gibberish(무의미 음절)가 고유명사로 오태깅되어 노출

- `nlp_analysis.py:169-176` — 태그가 `_KIWI_TAG_TO_POS`에 있고(`NNP`→`Noun`) 길이>1이며 불용어가 아니면 그대로 채택. Kiwi의 오태깅(미등록 음절을 NNP로 추정)을 검증하는 로직이 없음.
- `stopword_manager.py` — 사전 등재 불용어만 걸러냄(가변 gibberish는 사전에 없으므로 무력).
- `stopwords.json`의 `settings.min_word_length`/`max_word_length`는 **설정값이 존재하나 실제로 코드에서 읽혀 적용되는 곳이 없음**(grep 결과 0건) — 현재 죽은 설정.

## 4. 해결 방안

### 4-1. 반복 도배 — 연속 동일 토큰 Collapse (결정적 규칙, 추측 불필요)

**범위를 의도적으로 좁힌다**: "동일 단어가 문서 전체에서 여러 번 언급됨"(정당한 강조, 예: 긴 평가문 여러 문장에 걸친 "성실" 반복)과 "공백·구두점 없이 맞붙어 도배된 경우"는 다르다. 후자만 결함이다.

- 규칙: `_extract_meaningful_words_kiwi` 토큰 순회 중, **직전 토큰과 form·tag가 동일하고 시작 위치가 완전히 인접**(`token[i].start == token[i-1].start + token[i-1].len`, 즉 사이에 공백/구두점/다른 형태소가 전혀 없음)하면 같은 단어의 반복으로 보고 **1회로 합친다**(런 전체를 1개로 collapse).
- 이 규칙은 통계적 추측이 아니라 **토큰 위치(span) 비교**이므로 코퍼스 보정 없이 즉시 적용 가능.
- 정상적인 여러 문장에 걸친 반복 언급(`...성실함...수행함...성실하고...`)은 토큰 사이에 다른 형태소가 있으므로 영향 없음 — 결함만 정확히 표적.

### 4-2. Gibberish 제거 — 코퍼스 기반 임계값 보정 (단계적, 추측 금지 원칙 준수)

`score`(Kiwi 언어모델 점수)가 유력한 신호이나, 정상 희귀 형태소와의 경계가 임의 추측으로는 안전하지 않음(§2-(c)). 0617_01과 동일한 "데이터 주도 발굴" 절차를 따른다.

1. **코퍼스 감사 스크립트** 작성(`test/`) — 기존 취득 코퍼스(`acquired_sentences` 또는 `data/new_260617.csv`)와 실제 인사평가 문서 전수에 Kiwi를 실행하여, `NNP`/`SL` 태그 + 길이별 음절당 `score` 분포를 집계.
2. 분포에서 **정상 고유명사·드문 형태소 구간과 gibberish 구간의 분리 지점**을 사람이 검토(표본 샘플링) 후 임계값 확정 — 임의로 지금 숫자를 정하지 않는다.
3. 확정된 임계값으로 `_extract_meaningful_words_kiwi`에 필터 추가: 태그가 `NNP`이고 `score/len < threshold`인 토큰은 제외. (`NNG`는 사전 기반 일반명사라 오탐 위험이 낮아 제외 대상에서 뺀다 — 실제로 위 테스트에서 정상 `NNG`는 전부 임계 밖.)
4. 사전(stopword) 등재 단어는 태그/점수와 무관하게 항상 통과(이중 안전장치).

> 1단계(코퍼스 감사)는 분석만이라 비-🟡(코드 변경 없음)로 즉시 수행 가능. 2~3단계(필터 코드 추가)는 `nlp_analysis.py` 수정이라 🟡 승인 필요.

## 6. 영향 범위 / 제약

- **과거 저장된 분석 결과는 자동 개선되지 않음**: `meaningful_words`는 평가 생성/분석 시점에 1회 계산되어 DB에 저장됨. 수정 후 신규 분석부터 적용되며, 기존 데이터는 재분석(재실행)해야 반영됨. 일괄 재분석 필요 여부는 §8에서 결정.
- **배치 규모(약 1.9만 명, O(n) 유지 원칙)**: 두 수정 모두 문서 1건의 토큰 리스트를 1회 순회하는 **O(토큰 수)** 연산 — 평가자 간 비교나 전체 코퍼스 스캔이 아니므로 배치 성능에 영향 없음.
- **레거시 보호**: 기존 태그 매핑(`_KIWI_TAG_TO_POS`), 길이 필터, 불용어 필터는 그대로 유지. 추가 필터는 그 뒤에 additive로만 삽입.

## 8. 결정 필요 사항 (수행 전 확인)

1. **P1 착수 여부**: 4-1(반복 도배 collapse)은 결정적 규칙이라 즉시 구현 가능 — 승인 시 바로 진행.
2. **P2 착수 여부**: gibberish 코퍼스 감사 스크립트는 비-🟡(코드 변경 없음)이라 분석만 먼저 진행해도 무방. 결과를 본 뒤 P3 임계값을 함께 결정.
3. **기존 데이터 재분석 여부**: 과거 저장된 평가의 `meaningful_words`를 일괄 재계산할지(§6) — 대상 범위(전체 19,000명 vs 신규 데이터만)는 사용자 확인 필요.

4. **P2 코퍼스 감사 입력 데이터 출처 결정**: §4-2는 `acquired_sentences` 또는 `data/new_260617.csv`를 예시로 들었으나, 실제 감사에 사용할 데이터를 특정해야 한다. P2 스크립트 작성 전에 아래 중 선택 필요:
   - (a) `acquired_sentences`만 사용 — 인사평가 도메인에 특화
   - (b) `data/new_260617.csv`만 사용 — 대량·비정형 문장 포함
   - (c) 둘 다 사용 + 비교 분석 — 가장 안전하나 스크립트 복잡도 증가

5. **`nlp_config.json` gibberish threshold 키 이름 사전 정의**: P3에서 사용할 신규 키 이름을 P1/P2와 무관하게 지금 결정해야 수행 시 기존 키 오염을 방지할 수 있다. 아래 보기 중 선택:
   - (a) `gibberish_score_threshold` (직관적)
   - (b) `kiwi.gibberish_score_threshold` (kiwi 하위 키로 격리)
   - (c) `filter.gibberish_score_threshold` (필터 영역으로 분류)
