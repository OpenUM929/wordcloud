## 1. 배경 및 목적

긍/부/중 3분류는 **데이터 축 천장 3차 확증**(c5 silver ↓·c6 경계 gold ↓·c7 화행 멀티태스크 ↓)과
**모델링 축 천장 4차 확증**(8차: B 비대칭손실·C 임계값·E 대조학습 기각, 유일 순이득 = A 앙상블)에 도달했다.
현 배포 = seed45 단일모델(field-aware), 핵심가치(긍↔부 ≈ 0)는 달성 상태.

그러나 "천장"은 **지금까지 당긴 레버들의 천장**이지 시스템의 절대 한계가 아니다. 아직 안 당긴 축이 4+1개 있다:

1. **라벨 일관성**(데이터 품질 — 양을 늘리는 게 아니라 기존 라벨의 모순을 제거)
2. **가중치 공간**(수프/평균 — 앙상블 이득을 서빙비용 1배로 회수)
3. **캘리브레이션 서빙 배선**(이미 검증된 T scaling을 escalation 라우팅에 연결 — 사람 라벨 비용 절감)
4. **측정 인프라**(프로덕션 분포 홀드아웃 — n=140·±3pp 노이즈 한계 해소 + 재개 트리거 데이터 축적)
5. (조건부) **베이스 인코더 A/B 언블록**(8차 F — 기각이 아니라 환경 차단이었음)

목적: 위 레버들을 우선순위·성공기준·롤백과 함께 확정하고, 승인된 것부터 실측한다.
공통 목표 지표는 **중립경계(c3_neu149) 순이득**과 **측정 분산 축소**이며, 긍↔부 0은 불가침 게이트다.

- **불가능(재시도 금지)**: 쉬운 silver 대량, 경계 gold 소량 증강, 화행 멀티태스크, 손실/임계값형 결정층 레버 — 실측 기각.
- **가능(미시도)**: §4의 L1~L5. 전부 c4 라인 대조·4슬라이스·다중런 프로토콜 위에서 실측 가능.

## 3. 설계 원칙

1. **긍↔부 = 불가침 게이트**: baseline·8c_hard 전 런 0. 위반 즉시 기각. 중립→긍정 허용([[project_sentiment_core_value]]).
2. **실측 없는 채택 없음**: 모든 레버는 c4 라인(n_train 3979) 대조 A/B + 다중런(seed≥3 또는 fold≥5) 후에만 판정.
3. **배포물 불가침**: `model_out`·`model/hr_sentiment_finetuned` 미덮어씀. 채택 확정분만 별도 승인 후 반영.
4. **append-only**: gold/emotion.jsonl 기존 행 수정·삭제 금지. 라벨 정정은 동일 id 신규 리비전(`promote_gold` 규약).
5. **사람 라벨 정본**: L1·L4의 라벨 확정은 Claude prefill → 불일치·저확신만 사용자 escalation([[feedback_prefill_judgment_escalate_uncertain]]).
6. **GPU·서버는 사용자 승인 후**: 재학습(L2·L5)은 승인된 실행만, 서버 재시작은 사용자 몫.

## 4. 개선 레버 상세 (구현/수정 상세)

### L1. 라벨 일관성 감사 — 교차검증 기반 (우선순위 1 · GPU 소, 승인 필요)

**가설**: c5·c6·c7의 공통 실패 signature("gold를 더 넣으면 중립경계 오류가 **재분배**만 됨")는
학습셋 내부에 **서로 모순되는 중립경계 라벨**이 있을 때 나타나는 전형이다. 중립은 사람에게도 어려운 클래스라
([[project_neutral_is_the_hard_class]]) 3979행이 여러 시기·여러 절차(수동, prefill, 그룹감사)로 적립되며
기준이 미세하게 흘렀을 수 있다(예: 개선요청 화행은 2026-06-30에 중립→부정으로 재정 — 그 이전 적립분과 충돌 잔존 가능).
060630 감사는 긍↔부 오염만 봤고 **중립경계 일관성은 미감사**.

**방법** (confident-learning 방식, 신규 `scripts/label_audit_cv_r13.py`):
1. TRAIN 3979를 5-fold 분할, 각 fold를 나머지 4-fold 학습 모델로 out-of-fold 예측(`finetune_sentiment` 로직 재사용, 저장 안 함).
2. `(gold라벨 ≠ oof예측) ∧ (예측확신 상위)` 행을 의심 랭킹 — 특히 **같은 표면형·같은 field인데 라벨이 갈리는 쌍**을 자동 병치.
3. Claude가 의심 상위 ~200행 per-row 재판정 prefill([[feedback_no_group_stamp_per_row]]) → 라벨 변경 제안분만 사용자 확정.
4. 확정 정정은 동일 id 리비전 append → 재학습 → 4슬라이스 재측정.
5. **테스트 4슬라이스도 동일 감사**(모델은 train으로 이미 있음): 측정 노이즈 자체를 줄인다.

**성공기준**: 정정 후 재학습이 c3_neu149에서 단일런 1std(±3.4pp) 초과 개선 **또는** 슬라이스 간 회귀 없이 측정 분산 축소.
긍↔부 0 유지. 의심행이 거의 안 나오면 "라벨은 깨끗, 진짜 천장" — 그 자체가 가치 있는 확증(음성결과도 기록).

**롤백**: append-only 리비전이라 정정 이전 상태 재구성 가능. 재학습 산출물은 tmp 디렉토리.

### L2. 모델 수프 (가중치 평균) — 앙상블 이득의 1배 서빙 회수 (우선순위 2 · GPU 중, 승인 필요)

**가설**: 앙상블(+1~3pp·flutter 소거)은 유일 순이득이지만 K배 서빙이라 best-seed로 후퇴했다.
동일 베이스에서 파인튜닝된 seed들은 loss basin을 공유하므로 **가중치 평균(soup) 단일모델**이
앙상블 이득의 상당분을 서빙비용 1배로 회수하는 것이 정석이다. 증류(파이프라인 신설·기각)와 달리 수프는 **평균 한 번**이다.

**방법** (신규 `scripts/model_soup_r14.py`):
1. `ensemble_eval_r8_260708.py --save-seed {42,43,44,46} --save-dir model_out_seed{N}`로 4개 seed 재현 저장
   (seed45는 `model_out`에 있음 — 총 5개. 8차와 동일 코드경로라 재현성 확보).
2. uniform soup(5개 state_dict 평균) + greedy soup(dev에서 하나씩 추가하며 개선 시만 채택) 2종 산출.
3. 4슬라이스 측정: soup vs seed45 vs 앙상블(8차 기록) 3자 비교.

**성공기준**: soup가 seed45 대비 c3_neu149·8c_hard에서 우세하고 앙상블과의 격차 절반 이상 회수, **긍↔부 0(전 슬라이스)**.
**채택 시**: 별도 승인 후 `model/hr_sentiment_finetuned` 교체(06-25·seed45 백업 규약 준용, `VERSION.json` 재생성 —
`deploy/build_deploy.ps1`의 `Sync-Version`이 배포 시 자동 검증).

**리스크**: soup가 앙상블보다 못한 경우 흔함(그래도 seed45보다 나으면 이득). 최악 = seed45 유지(무손실).

### L3. T scaling 서빙 배선 + 신뢰도 기반 escalation (우선순위 3 · 재학습 0)

**가설**: 8차에서 T scaling은 ECE 절반·무손실로 검증됐지만 **정확도 레버가 아니라며 미배선**. 그러나 진짜 용도는
정확도가 아니라 **라우팅**이다: 판정패킷 prefill(status 1→2/3 분기)과 검토게시판 escalation이 신뢰도를 쓰는데,
현재 서빙 모델은 확률조차 반환하지 않는다(§2-2). 캘리브레이션된 신뢰도로 "사람에게 보낼 것"을 정확히 고르면
**같은 사람 라벨 예산으로 더 많은 hard gold**를 얻는다 — L4·능동학습의 효율 승수.

**방법**:
1. `hr_sentiment.py`에 확률 반환 경로 추가: `predict_proba(texts, fields=None)` (기존 `predict` 불변·argmax 동작 무변경.
   폴백 규약 동일: 실패 시 None).
2. `calib_thresh_r10_260708.py`의 T 적합 재사용 → dev로 T 1개 적합, 모델 디렉터리에 `calibration.json`(`{"temperature": T}`) 동봉.
3. `judgment_packet_service.py`의 패킷 생성에 캘리브레이션 신뢰도 필드 추가(선택 소비 — 기존 소비자 무영향).
   status 분기 임계는 **긍↔부 방향만 보수적으로**(의심 시 사람으로) 설정.

**성공기준**: escalation 큐의 적중률(사람이 실제로 라벨을 바꾼 비율) 상승을 다음 능동학습 사이클에서 실측.
argmax 라벨 자체는 T와 무관(τ 임계값은 8차에서 기각 — **argmax 결정은 건드리지 않는다**).

**리스크**: 낮음(후처리 상수·가역). `calibration.json` 없으면 기존 동작(하위호환).

### L4. 프로덕션 분포 홀드아웃 + 운영 능동학습 상시화 (우선순위 4 · GPU 0, 지속 트랙)

**가설**: 현 테스트셋은 n=140~398·규칙엔진 잔재 편향 표집이라 ±3pp 노이즈로 레버 판정력이 약하다(8차도 이 한계 명시).
지금 가동 중인 **장/단점 혼재 배치**는 field 부착 판정패킷을 처음으로 프로덕션 분포에서 생산한다.
이 검수 흐름(사용자가 어차피 보고서용으로 확정하는 라벨)의 부산물을 **학습이 아니라 측정에 먼저** 쓰면
"비-경계 fresh 광맥"(재개 트리거) 여부도 이 데이터가 스스로 답한다.

**방법** (스키마 신설 없음 — 기존 패킷·게시판 흐름 그대로):
1. 이번 혼재 배치 판정패킷에서 Claude per-row 판정 + 사용자 확정(진행 예정인 검수 작업과 동일 작업) →
   확정분 중 **일부를 학습 미투입 홀드아웃**으로 떼어 `TEST_SETS`에 `prod_YYMM` 슬라이스 등록(누수 0, sa_speech74 전례 준용).
2. 나머지 확정분은 `promote_gold`로 적립하되 **즉시 재학습하지 않는다** — c5·c6 교훈(경계 gold 소량은 재분배만).
   재학습 트리거 = prod 슬라이스에서 **현 모델의 체계적 오류 패턴**(특정 화행·표현군 클러스터)이 관측될 때만.
3. 사이클마다 홀드아웃 누적 확대(목표 n≥400 → ±1.5pp 분해능) — L1·L2 판정의 측정 기반이 함께 좋아진다.

**성공기준**: prod 슬라이스 n≥400 도달, seed45(또는 soup)의 prod 분포 성적표 확보. 이것이 곧 보고서의 정본 수치.

### L5. (조건부) 베이스 인코더 A/B 언블록 — 8차 F 재개 (우선순위 5 · GPU 중, 승인 필요)

8차 F는 **기각이 아니라 SSL 프록시 차단으로 미실행**. KoTE 44감정 프리트레인이 3분류 경계(특히 중립)에
편향일 가능성은 여전히 미검증 가설이다. **언블록 = 사용자가 프록시 밖 환경에서 `klue/roberta-base`를 수동 수급**
(HuggingFace 페이지에서 파일 다운로드 → 로컬 디렉터리 배치)하면, `finetune_sentiment.py` base 교체 A/B(seed 3)로 즉시 실측 가능.
동일 TRAIN·field-token·4슬라이스. 성공기준 = 4슬라이스 전반 우세 + 긍↔부 0. 수급 불가하면 본 레버는 계속 보류.

## 8. 리스크 및 제약

- **L1 최대 리스크 = 기준 재유동**: 재판정이 라벨 기준을 또 흔들면 역효과. 방어 = 확정 원칙 문서
  (끝맺음 없으면 중립·개선요청은 부정·양가태도는 기업관점 긍정)를 프리필 프롬프트에 고정, 사용자 확정만 반영.
- **L2**: soup가 seed45 이하면 무이득(그러나 무손실·측정으로 종결). seed 재현 학습 GPU 4런 비용.
- **L3**: 신뢰도 필드를 기존 UI가 오해석할 여지 — 선택 소비 원칙으로 차단, 게시판 표시 변경은 범위 외.
- **L4**: 검수 속도에 종속(사용자 시간). 홀드아웃/학습 분리 규율 미준수 시 누수 — 등록 스크립트에서 id 교차검사.
- **측정 한계 지속**: prod 슬라이스 n 확보 전까지 c3_neu149 ±3.4pp 분해능 — P1·P2 판정은 다중런 평균 필수.
- 대규모 사람 화행라벨(수천 행 캠페인)은 본 계획 범위 외 — L4가 그 축소·지속 버전이며, L4 데이터가 필요성을 판정.

## 9. 결정 필요 사항

1. **레버 승인 범위**: L1~L4 전부 진행 vs 일부만. **권장 = L1+L2 우선**(둘 다 c3_neu149 직접 타격, 병행 가능),
   L3·L4는 GPU 없이 진행 가능하므로 함께 착수 무방.
2. **GPU 실행 승인**: L1(5-fold ≈ 5런) · L2(seed 재현 4런) — 기존 위임 규약대로 Claude 실행. 승인 여부.
3. **L5 수급**: `klue/roberta-base`를 프록시 밖에서 수동 다운로드해 주실지 (미수급 시 L5 보류 유지 — 무방).
4. **L1 재판정 원칙 확인**: 개선요청=부정·무종결=중립·양가태도=긍정 기준을 프리필에 고정하는 것으로 확정해도 되는지
   (기존 확정 사항의 재확인 — 변경 아님).
