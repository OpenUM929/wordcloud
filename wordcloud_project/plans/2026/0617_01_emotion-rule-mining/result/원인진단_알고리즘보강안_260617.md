## 2. 왜 이런 결과가 나왔나 — 3층 인과

### 층1. 모델 (도메인 미스매치)
KoTE는 구어/SNS 감정 44분류 모델. 인사평가 **역량 명사구**(`리더십`, `업무전문성`, `목표를 위한 구체적 전략 제시`)에는 KoTE가 학습한 감정 신호가 거의 없다. → 확률분포가 **평평하고 저신뢰**(top 점수 중앙값 0.254). 긍정 신호가 뚜렷이 떠오르지 못한다.

### 층2. 매핑 (구조적 부정 편향)
44감정→3계열 정적 매핑이 **부정 25칸 / 긍정 16칸 / 중립 3칸**. 점수를 **계열별로 합산 후 argmax**하므로, 분포가 평평할수록 부정 칸 수(25)가 많아 `negative_score`가 구조적으로 유리. 긍정이 이기기 어렵다.
- `emotion_analysis.py:181-217` (합산 후 단순 최대, 임계값·동률처리 없음).

### 층3. 보정 — `rule3_last_low` (★ 직접 원인) + 긍정 구제 부재
`perspective_service.py:364-366`:
```
# 규칙 3: 반전 없이 마지막 + 저신뢰도 + strength>0.5 → 부정 전환
if (is_last and confidence < threshold(0.20) and strength > 0.5):
    return -strength, 'rule3_last_low'
```
- 단문(=`is_last=True`) + 저마진(`|pos-neg|<0.20`, 도메인 미스매치의 필연) + `pos+neg>0.5` → **무조건 부정(-strength)으로 강제**.
- 인사평가 단문 강점들이 정확히 이 조건(저마진·중간 strength)에 들어맞아 **긍정/중립이 부정으로 강등**됨. → 모델=negative 150건 정밀도 0%의 유력한 직접 원인.
- 게다가 보정 목록에 **긍정 구제(positive rescue)가 전무**(`NEGATIVE_IMPLYING_WORDS`/`STRONG_NEGATIVE_PHRASES`/`NEUTRAL_KEYWORDS`만 존재, L277-317). 한번 중립/부정으로 떨어지면 긍정으로 되돌릴 경로가 없다.

> ⚠️ `rule3_last_low`는 **중립/긍정 → 부정** 전환을 일으킨다. 이는 핵심 가치(긍↔부 오분류 방지, 중립→부정 불허)에 **정면으로 위배**되는 동작이다. 원래는 완곡 부정을 잡으려는 의도였으나, 저마진 단문 전반을 부정으로 끌어내려 과탐의 핵심이 됐다.

## 3. 규칙성 요약 (마이닝 결과)

1. **단문 + 명사 나열형 강점** → 평평 분포 → (매핑 부정편향 + rule3) → 부정/중립. (예: `리더십, 업무전문성, 창의력`, `전문성, 업무열의`)
2. **무응답/낙서** (`잘 모르겠습니다`, `ㅇㅇㅇ`) → 부정 또는 중립. 실제론 중립이어야 함.
3. **진짜 부정**(강요형 수직 리더십, 마이크로매니지먼트)은 **완곡·간접 표현**이라 KoTE가 못 잡음 → 중립 처리.
4. **`~하지 않음`형 칭찬**(`불필요한 업무지시를 하지 않음`)은 부정어(`않음`) 때문에 부정 위험.

## 4. 보강 방안 (가설 — step3 테스트로 검증)

### A. (권고) `POSITIVE_IMPLYING_PHRASES` + `positive_rescue` 신규 분기 — 계획 §6
- HR 긍정 표지(구문 단위): `리더십`, `전문성`, `소통`, `성과`, `업무열의`, `책임`, `청렴`, `안전`, `자기개발`, `학구열`, `목표 ... 제시`, `자발적 참여 ... 유도`, `솔선수범`, `모범`, `공감능력` 등 — **데이터(neutral→positive 303 + negative→positive 123)에서 빈출 표지로 확정**.
- 발동(보수적): 표지 포함 **AND** 반전 표지 없음(`not has_contrast`) **AND** base `neg` 낮음 **AND** 완곡부정 표지 없음 → 긍정 상향.
- **`rule3_last_low`보다 앞에 배치**하여 단문 강등을 사전 차단.
- 핵심가치 안전장치: neg 게이트 + 완곡부정/반전 제외 → **true-negative→positive 반전 원천 차단**.

### B. `rule3_last_low` 발동 조건 정밀화
- HR 긍정표지 문장은 rule3 제외. (rule3 자체 수정 = 레거시 영향 큼)

### C. 매핑/합산 구조 보정 — 계획 §6-3 (b)/(c)
- 클래스 크기 정규화(부정25 vs 긍정16) 또는 top-emotion 방식, argmax 마진 임계값. 전 KoTE 소비처 파급 → 별도 영향도 분석 필요.

## 5. ⚠ 결정 필요 — 레거시 보호와의 충돌

방안 A를 `rule3`보다 앞에 두면, **기존 rule3가 발동하던 행의 결과가 바뀐다**. 이는 계획 §5-3의 "기존 7 rule_id 발동행 score 완전 동일" 회귀 단언과 **충돌**한다. 그런데 바로 그 rule3 행들이 우리가 고치려는 오류(정밀도 0%)다.

→ **선택 필요**: ① A를 도입하고 "rule3 발동행 불변" 단언을 *문서화된 오류 행에 한해* 완화 / ② rule3 조건 정밀화(B) / ③ 구조 보정(C). 권고는 **①(A 도입 + 완화)** — 가장 국소적이고 핵심가치에 안전.
