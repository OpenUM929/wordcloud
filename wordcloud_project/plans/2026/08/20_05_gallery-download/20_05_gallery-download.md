## 1. 배경 및 목적

저장 갤러리 다운로드 모드에서 세 가지 문제가 보고됐다: (1) 체크박스가 아닌 카드 아무 곳을 클릭해도 선택이 토글되어 실수 선택이 잦다, (2) 다운로드 모드 진입 시 전체 데이터를 불러오는 로딩이 길다, (3) 실제 다운로드(ZIP) 실행 중 아무 피드백이 없어 멈춘 것처럼 보인다. 세 문제를 각각 원인 확인 후 개선한다.

## 2. 현재 시스템 분석

### (1) 카드 전체 클릭 선택 토글

- `buildGalleryCard(item)`(`deploy_gallery.html:1173`)의 `card.onclick`(1212~1224행)이 `downloadMode`(또는 `deleteMode`)일 때 카드 어디를 클릭해도 체크박스를 토글한다. 체크박스 자체는 `event.stopPropagation()`으로 별도 처리되어 있어(1196행) 중복 로직이 이미 존재 — **의도된 UX(빠른 선택)였으나 사용자는 실수 유발로 느낌**.

### (2) 다운로드 모드 진입 로딩

- `toggleDownloadMode()`(1269행)가 진입 시 `_loadAllForDownload()`(1502행)를 1회 호출 — `GET /api/perspective/deploy-gallery/list?all=1`.
- `gallery_db_service.list_entries(fetch_all=True)`(`gallery_db_service.py:147`)는 이미 "슬림 페이로드"로 최적화되어 있다(204~222행 주석: "전 행 images/row_results JSON 파싱·MB 단위 전송 제거 → 서버 CPU·전송량↓") — `id, employee_id, deploy_name, batch_title, timestamp, output_mode, source` 7개 컬럼만 반환, 페이지네이션·날짜 범위 제한 **없이 테이블 전체**를 대상으로 한다.
- 로컬 개발 DB(`wordcloud_project/.sessions/deploy_sessions.db`) 실측: `SELECT COUNT(*) FROM gallery_entries` = **0건**(2026-08-20 확인, 개발 환경은 배치 실행 불가·CSV만 반입하는 환경이라 실사용 데이터 없음) — 따라서 오늘 이 자리에서 실제 로딩 시간을 실측하지는 못했다. 다만 이 프로젝트 배치 규모가 약 1.9만 명(DL-3)이고, 저장 갤러리는 직원별로 제출용 저장 1회당 항목 1개, 그래프 저장 1회당 1개, 매트릭스 저장 1회당 1개가 누적되므로 **운영 환경에서는 이 테이블이 시간이 지날수록 수만 행까지 늘어날 수 있는 구조**다. "무제한 전체 로드"는 테이블이 커질수록 구조적으로 느려질 수밖에 없다 — 지금 느린 게 확인되지 않아도 사전 대비가 맞는 방향.
- **결론**: 컬럼(무엇을 가져오는가)은 이미 가볍다. 문제가 될 수 있는 것은 스코프(얼마나 많은 행을 가져오는가)다.

### (3) 다운로드 진행 중 무반응

- `executeDownload()`(1710행)는 `await fetch(...)` → `await res.blob()` 사이 어떤 진행 표시도, 버튼 비활성화도 하지 않는다(1710~1739행 전체 확인). ZIP 생성·전송에 시간이 걸리면 화면이 그대로 멈춘 것처럼 보인다 — 사용자 보고와 정확히 일치.

## 3. 구현 상세

### 3.1 백엔드

- (1)(3)은 프론트엔드만 변경. (2)는 백엔드 변경 없음 — 이미 슬림 페이로드이므로 컬럼을 더 줄일 필요는 없고, 프론트엔드가 무제한 `all=1` 대신 **기간 스코프**(예: 최근 N개월, 사용자가 조정 가능)를 기본값으로 요청하도록 바꾼다. 서버는 이미 `date_from`/`date_to` 파라미터를 지원한다(`perspective_routes.py:1315~1316`, `gallery_db_service.py:173~179`) — 활용만 하면 됨.

### 3.2 프론트엔드

- **(1) 체크박스 전용 선택**: `buildGalleryCard`(1212~1224행)의 `card.onclick`에서 `downloadMode`/`deleteMode` 분기의 토글 로직을 제거하고, `openDetail` 호출(미리보기)만 남긴다(요구사항 원자화 1.2에 따라 이 미리보기는 기존 `openDetail` 그대로 유지·재구현 없음). 체크박스는 1195~1196행 그대로(변경 없음).
- **(2) 로딩 축소**: `_loadAllForDownload()`(1502행)의 기본 요청에 `date_from`(예: 최근 6개월 — 정확한 기본값은 사용자 확인 필요, §요구사항 원자화 추가 예정)을 추가하고, 다운로드 모드 패널에 "기간 확장" 옵션(전체 조회로 되돌리는 버튼)을 둬 필요할 때만 전체를 불러오게 한다.
- **(3) 다운로드 진행률**: `executeDownload()`(1710행)를 `res.blob()` 단일 호출 대신 `res.body.getReader()`로 스트리밍 읽기로 바꾸고, 응답 헤더 `Content-Length`가 있으면 수신 바이트/전체 바이트로 퍼센트 게이지를 표시, 없으면(청크 인코딩 등으로 헤더가 없을 경우) 기존 `saveDeploy()`/`saveGraph()`의 경과 시간 표시 패턴(예: `formatElapsed`)을 재사용해 최소한 "다운로드 중… 경과 N초"라도 보여준다. 버튼은 진행 중 비활성화.
