## 0. 왜 했나

04_01~04_03 은 전부 **보고서 주변 정비**였다. 산식은 맞게 고쳤지만 보고서 본문은 나아지지 않았고, 오히려 🔴 미해소·미착수가 늘어 **더 미완성으로 보이게** 됐다. 사용자 지적("나는 보고서의 완성도를 높이고 싶은데 왜 계속 작업만 하냐")을 받고 본문을 직접 진단한 결과, 완성도를 깎던 것은 산식이 아니라 아래 셋이었다.

1. **문서 첫 화면이 자기 탄핵** — 구축완료·인사처본은 1~46행이 "폐기·인용 금지" + 오류 16항목 대조표
2. **결론 자리에 영원히 충족 불가한 조건** — 정본 §2-3 이 "🔴 1순위 = 발주기관 확인서 9종 요청"인데 **발주기관·과업지시서·계약서가 없다**(내부 작업). 확인해 줄 상대가 없는 것이 1순위 결론이면 보고서는 정의상 완성될 수 없다
3. **개정 이력이 본문에 눌어붙음** — 절 제목마다 `(2026-07-30 신설)`, 미해소 고지가 5곳 중복·상호 불일치, 04_01~03 결과 미반영

### 1-4. 조사 중 드러난 별건 — README 오안내 (수정 완료)

`27_03_completion-report/README.md`(04_03 에서 내가 만든 것)가 **인사처 실무자를 폐기 문서로 안내**하고 있었다. 정본은 **원페이퍼 + 상세 2종뿐**이고, 구축완료·인사처본은 구판이다. README §1 을 정본/구판 분리 구조로 교체했다.

🔴 **파생 문제(미해결)**: 인사처결과보고서(846행)가 유일한 평문 문서였는데 구판이라, **비개발 독자용 정본이 원페이퍼(245행)뿐**이다.

**2026-08-04 — 후속 작업 `08/04_05_legacy-report-restore` 로 이관·해소.** 이 자리에 처음 적은 "정정 14건 미반영"은 배너 문구를 검증 없이 옮긴 것이었고, 그것을 고쳐 적은 **"미반영 3건"도 틀렸다**. 항목별 취소선 유무만 보고 판정해 **부분 반영을 반영 완료로 셌기 때문**이다. 실제로는 ⑦(부분 반영)·②(전제가 살아 있음)가 더 있었고, ③은 표 1개가 아니라 **문서 전반의 계열 20개 지점**이었다.

가장 큰 오판은 **"③을 교체하면 §1-2-2 논증이 무너진다"** 였다. 표를 넣은 목적은 *3개 연도가 같은 결과를 낸다 = 구조적 특성* 이고, 정본(상세 §6-2)으로 교체하면 연도 간 최대 편차가 **0.6%p → 0.2%p 로 좁아져 논지가 오히려 강해진다.** 정본에 값이 전부 있어 승인이 필요한 판단도 없었다. → 상세는 `04_05_legacy-report-restore/_RESUME.md`
