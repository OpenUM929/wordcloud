# 13_01/13_02/13_03 실동작 검증용 테스트 데이터 — 예상 결과 및 절차

> 이 문서는 3개 계획서(`13_01_batch-merge`, `13_02_stopword-import`, `13_03_stopword-paging`)를
> 사용자가 실제 화면에서 검증할 때 쓰는 **하나의 시나리오**를 다룬다. 서버는 사용자가 직접 기동한다
> (Claude는 DL-12 에 따라 서버를 대신 기동하지 않는다).
>
> 아래 "예상 결과" 수치는 추측이 아니라, 실제 프로덕션 코드 경로(`StopwordManager.add_stopwords_bulk`,
> `is_stopword`, `NLPAnalysis._extract_meaningful_words_kiwi` 와 동일한 Kiwi 토큰화 규칙)를
> 오프라인 스크립트로 그대로 재현해 **실측**한 값이다. 실제 워드클라우드는 개별 평가의
> `nlp_analysis_results.meaningful_words`(형태소 분석 시점에 이미 불용어 필터가 적용된 값)를
> 합산해 그리므로, 지금 이 실측값과 원리적으로 동일해야 한다.

## 2. 절차

### Step 1~2 — 배치 2개 생성 (13_01 사전 준비)
1. 통합 데이터 업로드 화면에서 `평가데이터_배치A_260813.csv` 업로드 → 컬럼 매핑(아래 표) → 배치 생성.
2. 같은 화면에서 `평가데이터_배치B_260813.csv` 업로드 → (매핑은 동일하므로 "이전 매핑 불러오기" 사용 가능) → 배치 생성.

| CSV 컬럼 | 매핑할 필드 |
|---|---|
| 직원ID | `target_employee_id` (필수) |
| 부서 | `target_employee_department` |
| 직책 | `target_employee_position` |
| 평가일자 | `evaluation_date` |
| 장점 | `evaluation_document_strength` |
| 단점 | `evaluation_document_weakness` |

두 배치 모두 생성 완료 후 총 6명(E001~E006)의 평가가 있어야 한다.

### Step 3 — 배치 병합 (13_01)
1. `/admin/batch-management` 에서 방금 만든 배치 2개를 체크박스로 선택.
2. 「선택 배치 병합」 클릭 → 이름 입력 → 확인 대화상자(대상 배치·총 평가 건수 확인) → 병합 실행.
3. **확인**: 병합된 배치 하나에 평가 6건(직원 6명)이 모두 들어있는지, 목록에서 원본 배치 2개는
   더 이상 보이지 않는지(숨김 처리), 관점분석의 배치(회차) 축이 병합 배치 하나로 표시되는지.

### Step 4 — 일반 불용어 일괄 업로드 (13_02)
1. `/settings#stopwords` → 「일반 업로드」 → `일반_불용어_업로드_테스트.csv` 선택.
2. 카테고리 선택: 드롭다운은 **기존 카테고리만** 나오므로(`인명` 제외) **「명사」**를 선택한다
   (관련/내용/부분/이번/해당은 의미상 명사 필러에 해당).
3. 미리보기 → 등록(commit).
4. **확인**: 등록 5개(신규), 중복 0, 무효 0.

### Step 5 — 이름 일괄 업로드 (13_02)
1. 같은 화면에서 「이름 업로드」 → `이름_업로드_테스트.csv` 선택 (카테고리 선택 UI 없음 — 항상 `인명`).
2. 미리보기 → 등록.
3. **확인**: 등록 7개(신규), 중복 0. `src/configs/stopwords_names.json` 파일이 새로 생성되고
   `src/configs/stopwords.json` 에는 이름이 섞여 들어가지 않는지 확인(PII 분리, DL-9).

### Step 6 — 워드클라우드 재확인 (13_01+13_02 통합 확인)
병합된 배치의 워드클라우드를 다시 조회해 §3의 "업로드 후(after)" 표와 대조한다.

### Step 7 — 페이징 화면 확인 (13_03)
`/settings#stopwords` 화면에서 불용어 목록 하단 페이지 번호 영역이 **세로로 길게 늘어나지 않고
가로 한 줄**로 표시되는지 확인한다(수정 전에는 좌측 네비 CSS가 페이징의 `<nav>` 래퍼에 그대로
적용돼 전체 높이만큼 늘어나는 버그였음).

## 4. 🔴 알아둘 점 — 이름 업로드가 "부분"만 지워지는 경우

`이름_업로드_테스트.csv` 에는 실명 7개(김민준·박서연·이도윤·최지우·정하윤·강주원·한상철)를
모두 넣었지만, **실측 결과 실제로 사라지는 건 최지우·정하윤 2명뿐**이다. 나머지 5명은 다음과
같이 동작한다(형태소 분석기 Kiwi 가 이름을 인식하는 방식에 따라 갈리는, 실제로 관찰된 동작):

| 이름 | 실제 토큰화 결과 | 업로드 후 워드클라우드 |
|---|---|---|
| 최지우 | `최지우`(3글자 그대로 한 단어) | 사라짐 — 업로드값과 정확히 일치 |
| 정하윤 | `정하윤`(3글자 그대로 한 단어) | 사라짐 — 업로드값과 정확히 일치 |
| 김민준 | `김민`+`준` 으로 쪼개짐(`준`은 1글자라 애초에 워드클라우드 후보에서 제외) | **`김민`이 빈도 2로 계속 남음** — 업로드한 문자열("김민준")과 실제 토큰("김민")이 달라 매칭 실패 |
| 강주원 | `강주`+`원` 으로 쪼개짐 | **`강주`가 빈도 2로 계속 남음** — 위와 동일 이유 |
| 박서연 | 통째로 다른 형태(1글자 단위)로 쪼개져 애초에 워드클라우드 후보에 안 들어감 | 원래부터 안 보임 — 업로드 여부와 무관 |
| 이도윤 | 위와 동일 | 원래부터 안 보임 |
| 한상철 | 위와 동일 | 원래부터 안 보임 |

즉 이 시나리오로 검증하면 「이름 업로드」 기능이 **"업로드한 문자열이 실제 형태소 분석 결과와
정확히 일치할 때만" 필터링됨**을 확인할 수 있다. 만약 실제 운영에서 이런 잔여 이름 조각(예:
"김민")이 워드클라우드에 보이면, 그 조각 자체를 「일반 업로드」나 「이름 업로드」에 추가로
등록하면 된다 — 이번 기능은 정확히 그런 보완적 사용을 염두에 두고 설계된 것이므로 버그가
아니라 형태소 분석기의 알려진 특성이다.

## 5. 산출 방법(재현 가능)

이 문서의 수치는 다음 순서로 재현했다(서버 미기동, 오프라인):
1. `NLPAnalysis._extract_meaningful_words_kiwi` 와 동일한 규칙(NNG/NNP/SL/VV/VA, 길이>1,
   인접 반복 collapse)으로 위 CSV 6명분 장점+단점 텍스트를 Kiwi 로 직접 토큰화.
2. `StopwordManager` 를 실제 코드 그대로 사용하되 임시 경로로 격리해 (a) 현재 배포된
   `stopwords.json` 만 적용한 상태, (b) 거기에 `add_stopwords_bulk(..., target='general')` /
   `target='names'` 로 §2 CSV 값을 반영한 상태 — 두 상태 각각에서 `is_stopword()` 를 적용해
   최종 빈도표를 집계.
3. 실제 프로덕션 워드클라우드는 `perspective_service.py` 가 각 평가의
   `nlp_analysis_results.meaningful_words`(형태소 분석 시점에 이미 이 로직으로 계산·저장된 값)를
   합산할 뿐 재토큰화하지 않으므로, 위 실측값과 실제 화면 값은 원리적으로 같아야 한다.
