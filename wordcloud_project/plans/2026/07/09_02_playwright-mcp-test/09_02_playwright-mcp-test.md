### 3.2 Playwright MCP 설치 및 설정 — 두 가지 실행 모드

⚠️ **v1의 `--caps core,navigation,interaction,snapshot,screenshot`는 잘못된 값입니다.**
`npx @playwright/mcp@latest --help` 실측 결과, `--caps`가 받는 값은 **`vision, pdf, devtools`뿐**이며 navigation/snapshot/screenshot/interaction/network/console 관련 도구는 **core 기본 기능**으로 별도 캡 없이 항상 사용 가능합니다. 콘솔·네트워크 로그는 `--console-level`, `--output-mode`로 제어합니다.

| 모드 | 프로필명 | 플래그 | 용도 |
|------|---------|--------|------|
| 기능 테스트 | `playwright` (MCP 기본) | `--headless` | API/데이터/동작 검증, 자동화 고속 실행 |
| 상호작용 테스트 | `playwright-headed` (MCP 추가) | headed(no `--headless`) | 마우스 동작·CSS 클릭가능성·레이아웃 육안 확인 |

**설치 절차:**
1. `powershell -ExecutionPolicy Bypass -Command "npx -y @playwright/mcp@latest --help"` 실행 → **이 시점에 실제 옵션 목록을 재확인**한다 (버전업으로 옵션이 바뀔 수 있으므로 아래 설정을 맹신하지 말 것).
2. `powershell -ExecutionPolicy Bypass -Command "npx -y playwright install chromium"`
3. `opencode.jsonc`(프로젝트 루트, 없으면 생성)에 두 MCP 프로필 설정 추가:
```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "playwright": {
      "type": "local",
      "command": ["npx", "-y", "@playwright/mcp@latest"],
      "args": [
        "--browser", "chromium",
        "--headless",
        "--isolated",
        "--viewport-size", "1440x900",
        "--console-level", "warning",
        "--output-mode", "file",
        "--output-dir", "./wordcloud_project/plans/2026/0709_02_playwright-mcp-test/result/artifacts"
      ],
      "enabled": true,
      "timeout": 30000
    },
    "playwright-headed": {
      "type": "local",
      "command": ["npx", "-y", "@playwright/mcp@latest"],
      "args": [
        "--browser", "chromium",
        "--isolated",
        "--viewport-size", "1440x900",
        "--console-level", "warning",
        "--output-mode", "file",
        "--output-dir", "./wordcloud_project/plans/2026/0709_02_playwright-mcp-test/result/artifacts"
      ],
      "enabled": true,
      "timeout": 30000
    }
  }
}
```
- `--isolated`: 세션마다 쿠키/로그인 상태를 초기화해 테스트 간 오염을 방지 (§4.4 참조).
- `--viewport-size 1440x900`: §5 주제12.3 뷰포트 고정 요구사항을 설정 단계에서 강제.
- `--output-dir`: 스냅샷/콘솔/네트워크 로그를 §6 결과 보고 경로에 바로 축적.
- `playwright-headed`는 `--headless` 없이 headed 모드로 기동되어 마우스 동작·시각 확인에 사용.
4. opencode 재시작 → 두 playwright 서버 모두 초록색 연결 확인.

### 3.3 테스트 계정/데이터 준비 (신규)
- 아래 폴더가 아직 없으므로 **가장 먼저 생성**한다:
  ```
  mkdir -p wordcloud_project/plans/2026/0709_02_playwright-mcp-test/fixtures/batch_input
  mkdir -p wordcloud_project/plans/2026/0709_02_playwright-mcp-test/result/artifacts
  ```
- **관리자 로그인(§5 주제8.1)은 반드시 테스트 전용 관리자 계정을 사용**한다. 실제 운영 관리자 계정 자격 증명을 자동화 스크립트/설정 파일에 남기지 않는다.
- **배치 처리(§5 주제2)**: 사용자가 테스트할 배치 파일을 `fixtures/batch_input/` 폴더에 직접 배치한다. 시나리오 2.2에서 "파일 선택" 대신 **"폴더 선택"** 으로 해당 폴더를 지정해 업로드한다. 컬럼 스펙은 직원ID·평가텍스트·부서 등 실제 매핑 UI가 기대하는 형식을 따른다.
- 워드클라우드 개별 생성(§5 주제9)용 샘플 텍스트도 동일 fixtures 폴더에 고정한다 (재현성 확보).

### CSS 버튼 안 눌림 판정 상세 절차
1. `browser_snapshot` 으로 타겟 버튼 접근성 트리 확인
2. computed style 사전 점검: `pointer-events ≠ none`, `visibility = visible`, `display ≠ none`, `opacity > 0`, bounding rect가 뷰포트 내
3. `browser_click(ref)` 실행 → Playwright가 자동으로 액션 가능성(클릭 가능) 검사
4. 클릭 성공 시 상태 변화(로딩 스피너→완료) 관찰 → 미발생 시 FAIL
5. 타임아웃 발생 시 → CSS 차단(오버레이 겹침·z-index·pointer-events) 으로 판정
