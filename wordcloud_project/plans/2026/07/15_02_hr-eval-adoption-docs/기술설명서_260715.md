## 0. 5분 요약 (초록)

- **무엇**: 다면평가에 직원이 자유롭게 쓴 한 줄 코멘트를 읽고 **긍정 / 부정 / 중립** 셋 중 하나로 자동 분류하는 AI.
- **왜(변화)**: 예전에는 감정을 읽는 기능이 없어 **장점칸·단점칸 글자를 그대로 워드클라우드**(자주 나온 단어를 크게 그린 그림)로만 썼다. 즉 "어느 칸에 썼나"로만 긍·부를 가정했고 문장 뜻은 못 읽었다. 지금은 **문장의 뜻을 읽어** 판단한다.
- **핵심 결과 숫자 3개**(사람이 직접 매긴 정답지 = 검증셋 기준):
  1. **일반 대표 문장 97.7%** 정확
  2. 가장 치명적 오류인 **"칭찬↔불만 뒤바뀜" = 0건**(대표·고난도 문장셋)
  3. 실제 운영에서 **270만 문장을 98.8% 판정 완료**
- **믿어도 되는 이유 3줄**:
  (1) 가장 위험한 칭찬↔불만 뒤바뀜을 최우선으로 막았고 대표셋에서 0건이다.
  (2) 정확도는 일부러 어렵게 만든 사람 정답지로 측정했다(쉬운 문제로 부풀리지 않았다).
  (3) 더 많은 데이터·더 큰 모델을 여러 번 시험했지만 현 모델을 넘지 못했다(= 검증된 최선).

> ⚠️ **불리한 사실도 밝힌다(숨기지 않음)**: 사람도 헷갈리는 "중립 경계" 문장은 76.5%로 낮다. 이유와 안전장치는 §7. 완벽한 기계가 아니라 **가장 위험한 실수를 막은 뒤 나머지를 최대한 맞히는** 도구다.

> 🛡️ **가장 중요한 운영 원칙(공정성)**: 이 AI의 판정은 **부서·조직 단위의 참고용 집계 지표**(긍/부/중 비율·추세·워드클라우드)로만 쓴다. **개별 직원의 인사평가 점수에 자동으로 직접 반영하지 않는다.** 즉 AI가 사람의 점수를 매기는 게 아니라, 사람이 큰 그림을 보도록 돕는 도구다. (상세: §7-3. 실제 도입 시 이 정책은 인사처가 최종 확정한다.)

## 1. 무엇을 푸는 문제인가 (Before → After)

> **결론**: 예전 방식은 "글자 세기"였고, 지금은 "뜻 읽기"다.

### 1-1. 도입 전(Before) — 필드 워드클라우드
- 감정어(문장 뜻) 분석 기능이 **없었다.**
- 그래서 **긍정 필드(장점칸)·부정 필드(단점칸)에 쓴 글을 그대로 워드클라우드**로 만들었다.
- 한계:
  - 칭찬/불만 구분이 **"어느 칸에 썼나"로만** 정해짐 → 문장 자체의 뜻은 안 읽음.
  - 결과는 "무슨 단어가 많이 나왔나(빈도)"뿐 → **긍/부/중이 몇 %인지 알 수 없음.**
  - 같은 단어라도 맥락 구분 불가(예: 단점칸의 "꼼꼼함", 장점칸의 "어려움을 도와줌").

### 1-2. 도입 후(After) — 문장 뜻을 읽는 AI 감정 3분류
- 문장을 실제로 읽고 긍정/부정/중립을 **각각 판정**한다.
- 그 결과로 **비율·추세·부서 비교**가 가능해진다(예: "이 부서는 부정 코멘트 비율이 높다").

### 1-3. 왜 사람이 다 읽으면 안 되나 (규모)
- 최근 한 번의 재배치 코퍼스에서 분류 대상 문장이 **2,705,461개**였다(출처: 2025년 포함 배치 실적, `MODEL_SELECTION_REPORT_260715.md` §6).
- 사람이 270만 문장을 일관된 기준으로 읽는 것은 현실적으로 불가능하다. → 자동화가 필요하다.

## 2. 전체 처리 흐름 (파이프라인)

> **결론**: "글 한 줄"이 들어와 "긍/부/중 라벨"이 나오기까지 6단계를 거친다. 각 단계는 안전(개인정보·오분류 방지)을 위해 존재한다.
> ※ 파이프라인(pipeline) = 공장의 컨베이어벨트처럼, 작업이 정해진 순서로 자동으로 흘러가는 처리 과정.

```
 [1] 원본 코멘트          "보고가 조금 늦는 편입니다" (단점칸)
        │
        ▼
 [2] 가명화(개인정보 제거)  이름·사번을 가명/해시로 치환  ← 내부망에서만, 원본 식별자 비보관
        │
        ▼
 [3] 전처리 + 필드 부착     "단점 평가: 보고가 조금 늦는 편입니다"  ← 어느 칸(장점/단점) 글인지 표시
        │
        ▼
 [4] AI 판정(7/8 모델)      긍정? 부정? 중립?  → 확률로 계산 후 가장 높은 것 선택
        │
        ▼
 [5] 규칙 보정(안전망)      명백한 규칙 위반만 교정 (예: 개인 안녕·건강 언급 → 중립)
        │
        ▼
 [6] 저장·집계             결과 저장 → 비율/워드클라우드/부서 비교로 시각화
```

| 단계 | 하는 일 | 왜 필요한가(비전문가용) |
|---|---|---|
| 1 원본 | 다면평가 자유서술 코멘트 수집 | 판단 대상 |
| 2 가명화 | 이름·사번 등 개인정보를 가림 | **개인정보 보호**. 누가 썼는지 몰라도 감정은 판정 가능 |
| 3 전처리+필드 | 문장 정리 + "장점/단점 어느 칸" 표시를 문장 앞에 붙임 | 같은 말도 칸에 따라 뜻이 달라져서(§3-3) |
| 4 AI 판정 | 7/8 모델이 긍/부/중 **확률**을 계산해 가장 높은 것 선택 | 핵심 판단 |
| 5 규칙 보정 | 사람이 정한 명백한 규칙만 마지막에 덧씌움 | AI가 가끔 틀리는 정형 패턴을 **안전하게** 교정 |
| 6 저장·집계 | 결과 저장 및 통계·그림 생성 | 인사처가 실제로 쓰는 산출물 |

## 3. AI의 두뇌 = KoTE와 파인튜닝

> **결론**: 우리는 AI를 맨바닥에서 만들지 않았다. "한국어와 감정을 이미 아는" 공개 모델(KoTE)을 **바탕**으로 삼아, 그 위에 우리 인사평가 방식만 **추가로 가르쳤다**(파인튜닝).

### 3-1. KoTE란 무엇인가
- **KoTE** = 한국어 문장의 감정(기쁨·분노·실망 등 44종)을 **대규모 텍스트로 미리 학습**해 둔 공개 모델.
- 비유: **한국어와 감정 뉘앙스를 이미 아는 신입사원**을 데려온 것. 우리는 그에게 "우리 회사 인사평가"만 가르치면 된다.
- 기술 사실: KoTE는 한국어 온라인 텍스트로 사전학습된 언어모델(KcELECTRA 계열, 약 1.1억 개 파라미터) 위에 감정 라벨을 학습한 것. 우리 로컬 경로 `model/kote_for_easygoing_people/`.

### 3-2. 파인튜닝이란 (우리가 한 일)
- **파인튜닝(fine-tuning)** = 이미 똑똑한 모델에게 **우리 분야의 예시(정답)만 추가로 보여주며 미세 조정**하는 것.
- 비유: 요리 잘하는 셰프에게 "우리 식당 레시피"만 며칠 가르치는 것. 요리를 처음부터 가르치지 않는다.
- 구체적으로: KoTE의 마지막 "판단 층"을 **3분류(긍/부/중)** 로 바꾸고, 우리 인사평가 정답 약 4,000건으로 다시 학습했다.

### 3-3. 장점칸/단점칸 맥락을 어떻게 쓰나 (필드 신호)
- 같은 단어도 **어느 칸**이냐에 따라 뜻이 뒤집힌다:
  - 장점칸 "어려움을 **도와줌**" → 칭찬(긍정)
  - 단점칸 "소통에 **어려움**" → 불만(부정)
- 그래서 문장 앞에 칸 정보를 붙인다: `"장점 평가: …"` / `"단점 평가: …"`.
- 이 방식(필드 신호 주입)은 실측에서 효과가 확인됐다: 고난도셋의 칭찬↔불만 오류 **1→0**, 정확도 82.9→84.3% (출처: `status_260707.md` §1-1, 계획 0707_01).

### 3-4. 데이터가 외부로 나가지 않는다 (개인정보)
- 학습·판정에 쓰는 텍스트는 **가명화 완료분만** 사용(이름·사번 등 원천 식별자 비보관).
- 학습 데이터·산출물은 **내부망 배포에서 제외되는 폴더**(`plans/`)에만 둔다(배포 패키지에 미포함).
- 즉 **KoTE를 쓴다고 우리 데이터가 외부로 가는 게 아니다.** KoTE는 이미 만들어진 파일을 우리 내부에 내려받아 쓰는 것이다(로컬 실행).

## 4. 어떻게 배우는가 (AI와 규칙의 역할 분담)

> **결론**: 판단의 **주력은 AI**, 마지막 **안전망은 규칙**이다. 규칙은 명백한 것만 교정하고, 애매한 판단은 AI가 한다.

- **정답으로 배운다(지도학습)**: 사람이 "이 문장은 긍정" 식으로 매긴 예시(라벨)를 보여주면, AI가 스스로 패턴을 익힌다.
  - 라벨 등급: **gold**(사람이 확정한 정답) / **silver**(규칙·AI가 자동으로 붙인 참고 라벨, 신뢰도 낮음).
  - 학습에는 주로 gold를 쓴다(silver 대량 투입은 정확도를 떨어뜨림 — §스펙설명서 참조).
- **규칙의 역할(보정)**: "개인 안녕·건강 언급은 중립", "명백한 요청 표현은 부정" 등 사람이 정한 규칙을 **마지막 단계에서만** 덧씌운다. 규칙은 **칭찬↔불만을 새로 만들지 않도록** 설계돼 있어 안전하다.
- **핵심 원칙(불가침)**: **긍정↔부정 뒤바뀜을 막는 것이 최우선.** 중립→긍정 같은 덜 위험한 오차는 일부 허용해도, 칭찬을 불만으로(또는 반대로) 읽는 것은 최소화한다.

## 6. 정확도를 어떻게 측정하나

> **결론**: 사람이 직접 정답을 매긴 4종 "시험지(검증셋)"로 잰다. 일부러 **어려운 문장**을 많이 넣어 실력의 한계를 본다(쉬운 문제로 점수를 부풀리지 않음).

### 6-1. 검증셋(테스트셋)이란
- **검증셋** = 학습에 안 쓰고 따로 빼둔, 사람이 정답을 매긴 문장 묶음. 학생이 안 본 문제로 시험 보는 것과 같다.
- 우리 4종(총 **762건**의 사람 정답):

| 쉬운 이름 | 코드명 | 문항 수 | 무엇을 재나 |
|---|---|---:|---|
| 일반 대표 문장셋 | baseline399 | 399 | 평범한 실제 분포에 가까운 대표 실력 |
| 혼합·고난도 문장셋 | 8c_hard | 140 | 규칙이 못 풀고 넘긴 최난도 잔재 |
| 중립 경계 문장셋 | c3_neu149 | 149 | 긍·부·중이 애매한 회색지대 |
| 개선요청·완곡표현 문장셋 | sa_speech74 | 74 | "~하면 좋겠다" 식 완곡한 화법 |

### 6-2. 숫자 읽는 법
- **정확도** = 100문제 중 몇 개 맞혔나.
- **칭찬↔불만 오류(긍↔부)** = 칭찬을 불만으로(또는 반대로) 뒤바꾼 **건수**. **가장 치명적**이라 별도로 센다. 목표=0.
- 7/8 모델 성적:

| 검증셋 | 정확도 | 칭찬↔불만 오류 |
|---|---:|:---:|
| 일반 대표 | **97.7%** | **0** |
| 혼합·고난도 | **90.7%** | **0** |
| 중립 경계 | **76.5%** | 3 |
| 개선요청·완곡 | **83.8%** | **0** |

(출처: `MODEL_SELECTION_REPORT_260715.md` §3, 정합 재기준선 2026-07-14)

### 6-3. "정확도 97.7%"와 "판정률 98.8%"는 다른 숫자다 (오해 방지)
- **정확도(97.7% 등)** = 사람이 정답을 매긴 시험지(검증셋 762건)에서 **몇 개를 맞혔나**. → 실력 지표.
- **판정률(98.8%)** = 실제 운영 270만 문장 중 **몇 개를 (보류 없이) 분류해냈나**. → 처리량 지표.
- 둘은 재는 대상이 다르다. "운영 데이터 270만 건의 정확도"는 그 전체에 사람 정답이 없어 직접 못 재며, 실력은 위 검증셋 숫자로 갈음한다(표본으로 전체를 추정하는 것과 같다).

## 6-2. 남과 비교한 우리 위치 (객관적 잣대)

> **결론**: 위 숫자는 "우리가 만든 어려운 시험지" 기준이라, 외부와 곧바로 비교하긴 어렵다. 그래서 세 가지 외부 잣대로 위치를 세운다. **주의: 과제가 다른 공개 점수와 우리 점수를 직접 우열 비교하지 않는다.**

| 잣대 | 내용 | 무엇을 증명 | 상태 |
|---|---|---|---|
| ① 혈통(바탕모델 공개 성적) | 우리 바탕 KoTE/KcELECTRA는 공개 한국어 감정 벤치마크(예: **NSMC 네이버 영화평**)에서 **약 90%급**으로 공표됨 | 공개 최고수준급 재료 위에 지음 | 문헌 인용(가능) |
| ② 독립 앵커 | 우리 모델을 공개 세트에 그대로 1회 측정 | 제3자가 검증 가능한 외부 기준점 | GPU 승인 후 실측 예정 |
| ③ **사람 한계선(관측자 간 일치도)** | 같은 문장을 사람 여럿이 라벨 → 사람끼리 일치율 | 중립경계 76.5%가 **사람 한계에 근접**함 | 소규모 라벨 실험 예정 |

- **NSMC** = 네이버 영화평 20만 건으로 만든, 한국어 감정분석의 사실상 표준 시험지(긍/부 2분류). 유명 모델들이 약 90%를 보고한다.
- **왜 직접 비교 금지**: NSMC는 영화평·2분류, 우리는 인사평가·3분류·필드 맥락 → **문제 자체가 다르다.** "우리가 NSMC를 이겼다" 식 서술은 부정직하므로 하지 않는다. ①②③은 "위치 가늠"용이다.

### 6-4. 다른 방식·제품과 비교했나 (정직한 공백 고지)
- **레거시(도입 전) 대비**: 필드-only 워드클라우드는 애초에 "긍/부/중 비율"을 못 냈으므로, 문장 뜻을 읽는 지금 방식이 기능상 상위다(§1).
- **범용 LLM(예: 대형 언어모델) 제로샷 대비**: 우리 테스트셋에 직접 붙여 비교하는 것은 **아직 미수행(§6-2 ④, 승인 시 예정)**이다.
- **상용 감정분석 제품과의 비교**: **수행하지 않았다.** 대부분 한국어 인사평가·필드 맥락에 특화돼 있지 않고, 내부 데이터를 외부 서비스에 넣을 수 없어(개인정보·내부망) 동일 조건 비교 자체가 어렵다. → 이 공백은 숨기지 않고 밝힌다(C4).

## 7. 한계와 안전장치

> **결론**: 완벽하지 않다. 특히 "중립 경계"가 약하다(76.5%). 하지만 **가장 위험한 칭찬↔불만 뒤바뀜은 막았고**, 나머지는 사람도 어려운 회색지대다.

### 7-1. 못 맞히는 구간과 이유
- **중립 경계 76.5%**: "노력의 여지가 있음"처럼 칭찬인지 완곡한 지적인지 **사람도 갈리는** 문장. 이건 데이터·기술의 문제라기보다 **문장 자체가 애매**한 것이다(→ §6-2 ③으로 증명 예정).
- 반복 실측 결과, 데이터를 더 넣거나 모델을 키워도 이 구간은 안 올랐다(천장).

### 7-2. 안전장치 (칭찬↔불만 뒤바뀜 방지)
1. **최우선 지표로 감시**: 모든 실험에서 칭찬↔불만 오류를 첫 번째 합격 기준으로 둔다(대표·고난도셋 0 아니면 채택 안 함).
2. **규칙 보정은 중립 방향만**: 안전망 규칙은 새 칭찬↔불만을 만들지 않는다(개인 안녕→중립 등).
3. **위험한 개선은 기각**: 오류를 늘리는 데이터/모델은 성적이 좋아도 버린다(예: 대량 패턴 데이터가 칭찬↔불만 9건 유발 → 폐기, §스펙설명서).

### 7-3. 판정 결과의 사용 범위 (공정성)
> **결론**: AI 판정은 **집계·참고용**이다. **개별 인사점수에 자동 반영하지 않는다.**
- 산출물은 부서·조직 단위의 **긍/부/중 비율·추세·부서 비교·워드클라우드** 같은 집계 지표다.
- AI가 특정 개인의 코멘트를 "부정"으로 읽었다고 해서, 그 사실이 **그 사람의 평가 점수를 자동으로 깎지 않는다.** 최종 해석·판단은 사람(인사처)이 한다.
- 이렇게 두는 이유: 설령 개별 문장 하나를 틀리더라도(특히 애매한 중립경계) **한 직원이 그 오류로 불이익받는 경로 자체를 차단**하기 위해서다.
- ※ 실제 도입 시 "직접 반영/참고용"의 최종 정책은 인사처가 확정한다. 본 문서는 안전한 기본값(참고용)을 전제로 서술했다.

### 7-4. 오류가 발견되면 — 재검토·정정 절차
> **결론**: 사람이 언제든 뒤집을 수 있고, 정정은 다음 학습에 반영된다.
1. **발견**: 집계·검토 화면(그룹검토 게시판)에서 담당자가 이상 판정을 확인한다.
2. **사람 확정**: 담당자가 해당 문장을 올바른 라벨로 **직접 정정**한다(사람 확정 = gold). 이때 사람 판단이 AI 판정을 이긴다.
3. **반영**: 정정분은 정답지(gold)에 **누적 보존**(수정·삭제 없이 새 기록으로 추가)된다. 이 정정은 해당 건에 **즉시 반영**(사람 확정값이 표시됨)되고, 축적된 정정은 향후 재학습의 재료가 된다.
4. **모델 재학습은 별개·조건부**: 현재 모델은 정확도 천장 확증으로 **동결(freeze)** 상태다(§5, §스펙 §6). 즉 개별 정정은 언제든 되지만, 그것만으로 모델을 매번 다시 학습하지는 않는다. 재학습은 성능 저하·조직 변화 등 필요 시에만 하며(§7-6), 그때도 4종 검증셋에서 칭찬↔불만 0 유지를 확인한 뒤에만 배포한다(§8 부록M 단계6).
- 즉 **오류는 최종 상태가 아니라 사람이 즉시 정정·기록하는 대상**이며, 사람이 최종 통제권을 갖는다.

### 7-5. 못 판정한 1.2%는 어떻게 되나
> **결론**: 버리지 않는다. **보류로 분리**되어 필요 시 사람이 본다.
- 운영에서 98.8%(약 267만 건)가 자동 판정되고, 나머지 **1.2%(32,552건)는 공란·무의미·초단문** 등 **애초에 판정 대상이 아닌 입력**이라 보류로 분리된다(출처: `MODEL_SELECTION_REPORT_260715.md` §6).
- 보류분은 삭제되지 않고 **미판정 항목으로 집계에서 분리**되며, 필요하면 §7-4 절차로 사람이 검토한다. 즉 "AI가 어려워서 못 푼 문장"이 아니라 "판정할 내용이 없는 입력"이 대부분이다.
- 보류가 통계를 왜곡하지 않도록, 긍/부/중 비율은 **유효 판정된 건 기준**으로 계산한다.

### 7-6. 시간이 지나면 (유지보수)
> **결론**: 조직·말투가 바뀌면 **정기 점검 + 필요 시 재학습**으로 대응한다(전면 재제작 불필요).
- **정기 회귀감시**: 주기적으로 4종 검증셋을 재측정해 정확도·칭찬↔불만 0이 유지되는지 확인한다.
- **필요 시 재학습**: 새 표현·조직 변화로 성능이 흔들리면, 누적된 정정 gold로 §8 부록M 절차를 다시 돌린다(맨바닥 재제작이 아니라 미세조정 반복이라 저비용).
- **한 단계 위 후보**: 말투 적응을 더 원하면 DAPT(도메인 이어사전학습, §스펙설명서 §7)를 1회 시험할 수 있다.

> **목적**: "약간만 수정해 그대로 매뉴얼로" 쓰도록, **실제 파일·명령**을 순서대로 적는다.
> **전제**: 내부망 GPU 서버(약 6GB VRAM 이상), Python + PyTorch + transformers 설치. **모든 학습은 사용자 승인 후 실행**(서버 무단 실행 금지).
> **경로 기준**: `wordcloud_project/plans/_datasets/kote_finetune/`

### 단계 0 — 폴더·파일 확인
- 학습 스크립트: `scripts/finetune_sentiment.py`(정답 목록·검증셋 정의), `scripts/ensemble_eval_r8_260708.py`(배포 학습·측정)

```
python scripts/export_jsonl.py      # CSV → 약지도 JSONL(개인정보 제거 게이트 적용)
python scripts/build_splits.py      # 중복 제거 + 정보누수 방지 분할(GroupKFold)
```
- 산출: `emotion/weak_export_<날짜>.jsonl`, 품질 리포트 `result/export_report_*.md`, `result/split_report_*.md`.
- ※ 개인정보(이름·사번)는 이 단계에서 해시/제거된다.

- 학습에 쓰는 gold 목록은 `finetune_sentiment.py`의 `TRAIN_FILES`에 정의(약 4,015건).

### 단계 3 — A/B 실험(새 데이터 검증, 배포 모델 미덮어씀)


- 필드 신호: 문장 앞에 `"{장점|단점} 평가: {문장}"` 자동 부착(`--field-token on`).
- 출력: 시드별·앙상블 정확도, 슬라이스별 칭찬↔불만 오류.
- **합격 기준(게이트)**: 대표·고난도셋 칭찬↔불만 오류 = 0 **그리고** 중립경계가 배포 대비 명확 향상(±2σ 초과) 또는 편차 축소. 미달이면 **배포 안 함**.

### 단계 4 — 배포용 단일 모델 저장(합격 시에만)

- 앙상블과 **동일 코드경로**로 seed45 하나만 학습·저장(재현성 보장).
- 저장물: `config.json`, `model.safetensors`, 토크나이저, `calibration.json`.

### 단계 5 — 배포 반영
1. 저장된 모델 폴더를 `model/hr_sentiment_finetuned/`로 교체(기존은 `..._backup_<날짜>`로 백업).
2. **서버 재시작**(모델 메모리 재적재). ※ 서버 실행/재시작은 사용자가 수행.
3. 무결성 확인: 선언·디스크·메모리 3자 일치 검증(계획 13_01).

## 부록 B — 재현 정보(논문용)
