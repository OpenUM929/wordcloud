## 1. 요구사항 (사용자 확정)

1. 계획서들이 **독립 섬**으로 존재 — 어느 계획이 어느 계획에서 파생됐는지, 어느 CR과 연계됐는지 표현이 없다. **문서 간 연결 고리**를 만든다.
2. 간트차트는 **월 단위**로 본다. 파생/선행 계획이 **연관선으로 이어져** 보인다. **CR현황과도 연계**된다.
3. **간트는 별도 계획(데이터)을 갖지 않는다.** 기본은 **계획서 + `_index.md` + CR 문서를 조합**해서 만든다. (사용자: "간트는 별도로 계획을 갖지 않아. 계획서와 _index.md, CR 문서를 조합해서 만들꺼야")
4. 색상은 **간트차트의 각 그룹별(상태) 색상을 시스템에서 그대로 가져와** 쓴다.

## 2. 현재 시스템 분석 (코드 실측)

- **관리자 칸반보드**: `/admin/plans`. `wordcloud_project/web/templates/plans_kanban.html` + `wordcloud_project/src/routes/plans_routes.py`. 탭 ① 칸반보드 ② 월별 CR 현황.
- **계획서 데이터 파서**:

## 3. 설계

### 3.1 간트는 데이터를 갖지 않는다 — 3자 조합 (소유권 매트릭스)

```
_index.md(월별) ─┐  ← 막대 뼈대·상태색·날짜 + [신규] 관련CR·선행·에픽 컬럼
계획서 메타블록 ─┼─→ parse_all_months() 확장 ─→ GET /admin/api/plans/gantt ─→ 커스텀 SVG 렌더
CR 문서 ────────┘  ← _scan_all_crs() → ◆ 마일스톤·요청일·FP/공수
```

| 정보원 | 소유(정본) | 간트 기여 |
|--------|-----------|-----------|
| `_index.md` | 명부·상태·날짜 + **링크 3종 컬럼(정본)** | 막대·스윔레인·선행/CR 간선 |
| 계획서 메타블록/`## 관계` | 자기완결 미러(선택) + 복합 그래프(예외) | 링크 3개↑ 계획만 |
| CR 문서 | 요청일·FP·공수 + CR↔CR 리비전(`-r`/`Refs`) | ◆ 마일스톤 (CR 문서 자체는 수정 안 함, 역인덱스는 간트 라우트에서 `plan['related_cr'] → cr['req_id']` 매칭 결과를 메모리상 인덱스로 생성 — 별도 저장소 없음) |

### 3.2 링크 어휘 3종 (최소·확정)

`_index.md` 컬럼을 date 뒤에 3개 추가:

```markdown
| 계획서 | 작업 요약 | 상태 | 작성일 | 관련 CR | 선행 | 에픽 |
|--------|-----------|------|--------|---------|------|------|
| 14_04_gantt-chart | 간트차트 | Todo | 2026-07-14 | | 14_03 | kanban-linkage |
| 15_06_emp-id-match-fix | 사번 매칭 수정 | Done | 2026-06-15 | REQ-2606-030 | | |
```

| 컬럼 | 간선 | 조인 대상 | 간트 표현 |
|------|------|-----------|-----------|
| `관련 CR` | 계획 → CR(구현) | `CR_DIR/REQ-*.md` | ◆ 보라 점선 리더(CR 요청 → 이행 계획) |
| `선행` | 계획 → 계획(depends) | 같은/타월 `_index.md` 행 | 회색 곡선 의존 화살표 |
| `에픽` | 묶음 | 동일 태그 계획·CR | 스윔레인 그룹 |

- **ID 규칙**: 동월 참조 `DD_NN`, 타월 참조 `YYYY/MM/DD_NN`. 이름 슬러그가 아니라 **불변 좌표**로 매칭(단, plan id 전체 슬러그와 접두사/접미사 매칭, §5.1(d) 참조).
- **값 없으면 빈칸**(=간선 없음). 복수는 콤마+공백: `REQ-2606-030, REQ-2606-032`.

### 3.3 렌더러 — 커스텀 SVG (frappe-gantt 기각)

- **채택**: `mockup-gantt.html`이 프로토타입. HTML 막대(상태 3종 토큰) + 절대배치 + SVG 오버레이(주 그리드·오늘선·곡선 의존선·CR◆ 점선 리더).
- **기각: frappe-gantt** — 에픽 스윔레인, CR◆→막대 점선 리더, 곡선 커넥터를 네이티브 미지원. 커스터마이즈 비용이 자체 렌더러보다 크고 vendor 의존 추가. → 자체 렌더러로 vendor 0.
- **월 단위**: x축 = 월 세그먼트 + 주(7일) 그리드. 단일일 항목(Todo/Done)은 **점 마커**로 렌더(월뷰에서 소실 방지).
- **x축 월 범위**: `parse_all_months()`가 반환한 전체 월을 표시한다(현재 연도 내). 연도 경계 시 `PLANS_DIR`의 연도 폴더명(`YYYY`)을 기준으로 복수 연도 스캔(후속 확장, 초기엔 단일 연도).
- **막대 범위 규칙**:

  | 상태 | 시작 | 종료 | 표현 |
  |------|------|------|------|
  | Done | `_index` date | 메타블록 `완료일` 또는 폴더 mtime | 막대/점 |
  | Doing·Pre-Done | `_index` date | 오늘(동적) | 진행 막대 |
  | Todo·Hold·Drop | `_index` date | = 시작 | 점 마커 |

  → 시작=`_index` 단일 date, Done 종료만 `_find_main_md`가 이미 여는 메타블록 헤더에서 `완료일` 추가 추출(재사용). `완료일`이 메타블록에 없으면 폴더 mtime fallback. mtime은 git clone·복사 시 변할 수 있으므로 `git log --follow --format=%ci -- <main_md>` 우선 시도(옵션), 실패 시 mtime.

### 3.4 CR현황 탭 교체

- 탭 `📊 월별 CR 현황` → `📈 간트차트` (view id `git` 유지 → JS 최소 변경).
- `#crSummary`(월별 집계: 총CR/FP/공수/누적) **상단 유지**. 하위 아코디언 → 간트 컨테이너 교체.
- `switchView('git')` → `loadCrMonthly()`(요약) + `loadGantt()`(간트) 병렬.

### 4.2 #18 핵심 — **AI 필수 채움 게이트** (사용자 확정: 제안+확인, 자동 채움 강제)

> **계획서 작성 시 링크 3종 채움은 선택이 아니라 필수 단계다.** AI는 빠뜨림으로 빈칸을 남길 수 없고, 반드시 후보를 탐지·제시해 사용자 확정을 받는다. 이는 기존 지침 #14(요구 재확인: "AI가 먼저 예측 답을 채워 제시, 사용자 O/X")와 동일 흐름.

- **필수 채움 절차** (계획서 작성 워크플로에 편입):
  1. AI가 세 컬럼 후보를 **자동 탐지·기입**한다 —
     - `관련 CR`: 계획 본문 `REQ-\d{4}-\d{3}` grep + `CR_DIR` 실존 대조 (검증 가능한 사실 → 자동).
     - `선행`: 현 세션이 **파생된 직전 작업** + 초안 헤더 `선행:` 언급 (AI가 대체로 앎 → 자동).
     - `에픽`: `_index.md` 기존 에픽 태그 중 **같은 계열 재사용 후보** 제시 (제품 판단 → **힌트만**, 묶음 여부는 사용자 결정).
  2. AI가 사용자에게 채운 값을 제시하고 **O/X 확정**을 받는다.
  3. **"없음"도 확인을 거친 명시적 값**이다. 확인된 없음은 `-`로 표기하고, **아직 확인 안 된 필드는 빈칸으로 남긴다** — 이 구별(빈칸=미확인 / `-`=확인된 없음)이 작성 게이트·리뷰에서 미처리 필드를 식별하는 근거다. 미확인 필드가 남은 채 `Done` 금지.
  4. 추측 금지: 근거(grep 결과·파생 세션·기존 태그) 없이 간선을 지어내지 않는다.
- **강제(enforcement) 2층 분리** (린터 과신 교정):
  - **작성 게이트(AI+사용자)** — **"채움 여부"는 여기서만 강제된다.** AI가 후보 자동 기입 → 사용자 O/X. 사후 린터는 `_index.md` 텍스트만 봐서 **"확인된 빈칸"과 "안 채운 빈칸"을 구별할 수 없으므로**, 채움 여부를 판정하지 않는다.
  - **린터(Done 전환 게이트)** — 검증 가능한 위반만 담당: ① `관련 CR`·`선행` 좌표 실존(dangling 금지) ② 선행 DAG(순환 금지). 위반 시 Done 차단. 빈칸/미확인 판정은 하지 않는다.
- **§3.1과 모순 해소**: §3.1에서 메타블록 미러를 "선택"으로 둔 것과 §4.2 필수 채움은 대상이 다르다. **강제는 `_index.md` 컬럼(정본)에 대해 이뤄지며**, 메타블록 미러 유무는 사용자 자율이다. 정본이 채워졌으면 미러는 있어도 되고 없어도 된다(자기완결 편의).
- **자동 vs 판단 구분**: `선행`·`관련 CR` = 검증 가능 → AI 자동 기입. `에픽` = 제품 의도 → AI는 기존 태그 재사용만 제안, 신규 묶음은 사용자 소유.
- **규격**: 어휘 3종·ID 좌표(동월 `DD_NN`/타월 `YYYY/MM/DD_NN`)·`## 관계` 표(링크 3개↑ 복합 예외)·단일출처(정본=_index, 메타블록은 미러)·DAG(선행 순환 금지) 검증.
- **소급(백필)**: 과거 계획은 백필 스크립트가 후보만 제시, 역시 사용자 확인(자동 커밋 금지, §7).

## 5. 구현 상세

### 5.1 백엔드 (`plans_routes.py`)

- **(a) `_parse_index_md` 확장**(`:236` 루프): `TABLE_RE` 매치가 속한 **전체 소스 라인**을 `content.splitlines()[content[:match.start()].count('\n')]` 등으로 추출, `'|'` split 재분해해 5·6·7번째 셀 → `related_cr`(리스트), `depends`(리스트), `epic`(문자열)로 plan dict에 추가. 셀 없으면 빈값(하위호환). ※ 오해 주의: `match.group(0)`은 `TABLE_RE`가 캡처한 4셀(`| id | 요약 | 상태 | date |`)까지만 담으므로 전 라인 추출이 필수다.
- **(b) Done 종료일**: `:258-276` 메타블록 헤더 파싱 블록에 `완료일:\s*(\d{4}-\d{2}-\d{2})` 추출 1줄 추가 → `end_date`. `완료일`이 없으면 `완료일시:`(기존 보고서 파일)도 함께 시도(하위호환 fallback), 그래도 없으면 §3.3의 mtime/git log fallback.
- **(c) `parse_all_months` 재사용**: 반환 dict에 위 필드가 자동 포함(신규 파서 없음).
- **(d) 신규 라우트 `GET /admin/api/plans/gantt`**(`@admin_required`):
  ```
  plans  = parse_all_months()                     # 막대(+링크 컬럼)
  crs    = [c for c in _scan_all_crs() if c['date']]  # ◆ 마일스톤
  epics  = group by plan['epic']                  # 스윔레인
  deps   = plan['depends'] 좌표 → plan id 해소     # 선행 간선
  crlink = plan['related_cr'] → cr req_id 매칭     # CR 리더
  return {success, epics[], tasks[], milestones[], deps[], cr_links[]}
  ```
  **선행 좌표 해소 상세**: `DD_NN`은 plan dict의 `id`(전체 슬러그, 예: `14_03_kanban-board-guide`)의 일부이므로 정확 일치가 아니라 `_resolve_plan_folder`(`:176`)와 동일한 **접두사/접미사 매칭**을 사용: `ref == p['id'] or p['id'].startswith(ref + '_') or p['id'].endswith('_' + ref)`. 동월 참조(`DD_NN`)는 같은 month dir의 `_parse_index_md` 결과에서 lookup. 타월 참조(`YYYY/MM/DD_NN`)는 `parse_all_months()` 전체에서 `DD_NN` 접두사 매칭 AND `month == MM` 조건(plan의 `month` 키). 매칭 실패 시 해당 dep는 경고 후 스킵(린터가 별도 경고).
- **(e) 링크 린터(Done 전환 게이트)** — **검증 가능한 위반만**: ① `관련 CR`·`선행` 좌표 실존(dangling 금지) ② 선행 DAG(순환 없음). 계획서 저장 시 자동 실행, 위반 시 Done 차단(린터 통과가 Done 조건). **"미확인 빈칸" 판정은 린터가 하지 않는다** — 텍스트상 확인된 빈칸과 구별 불가하므로 채움 여부는 작성 게이트(§4.2)에서 강제. sentinel `-`(확인된 없음)는 작성 게이트·리뷰의 보조 신호일 뿐 린터 강제 대상 아님.
