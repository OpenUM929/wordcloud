# 관리자용 진행현황 보드(칸반보드) 도입 보고서

> **대상**: 임원·팀장 등 비전문가  
> **작성일**: 2026-07-14  
> **수치 기준**: 2026-07-14 운용 중인 시스템 실측

---

## 1. 왜 만들었나 (배경)

그동안 계획서는 폴더에 파일 형태로만 저장되어, 관리자가 **"지금 무엇이 진행 중이고, 무엇이 끝났는지"** 를 한눈에 알기 어려웠습니다.

- 90건 이상의 계획서가 폴더 속에 흩어져 있음
- 일일이 파일을 열어봐야 상태 확인 가능
- 월별 변경요청(CR) 현황도 따로 관리되어 업무 파악에 시간이 오래 걸림

## 2. 무엇인가 (설명)

**칸반보드**는 진행상태별로 업무 카드를 나열해 보여주는 전자식 업무 현황판입니다.

- 6개 상태 컬럼: **예정 → 진행 → 점검대기 → 완료 → 보류 → 폐기**
- 각 카드에는 **월·진행상태·작업유형·산출물 수**가 한눈에 표시
- 완료된 작업은 월별로 묶어 깔끔하게 정리
- 상단 탭 하나로 **계획서 현황**과 **변경요청(CR) 현황**을 바로 전환 가능
- **10초마다 자동 갱신** — 따로 새로고침할 필요 없음
- **관리자만 접속 가능** — 일반 사용자는 접근 불가 (보안 적용)

## 3. 주요 기능

| 기능 | 설명 |
|------|------|
| 📋 **상태별 컬럼** | 예정/진행/점검대기/완료/보류/폐기 — 6단계로 시각화 |
| 🔽 **월 필터** | 특정 월만 골라서 보거나, 전체 데이터를 한 번에 조회 |
| 🔄 **정렬** | 최신순/오래된순 전환 버튼 |
| 📦 **월별 그룹** | 완료된 작업은 월 단위로 묶어 표시, 클릭 시 일람 |
| 📊 **CR 현황 탭** | 변경요청을 월별로 집계, FP(기능점수)와 공수(시간) 함께 표시 |
| 🔔 **자동 갱신** | 새 계획서 등록 시 10초 내 반영 |

## 4. 현재 진행현황 (2026-07-14 기준)

### 계획서 현황 (총 **90건**)

| 상태 | 건수 |
|------|:----:|
| ✅ 완료 (Done) | **54** |
| 🔄 작업중 (Doing) | **8** |
| 🔶 점검대기 (Pre-Done) | **14** |
| 📋 예정 (Todo) | **9** |
| 📌 보류 (Hold) | **2** |
| 🗑️ 폐기 (Drop) | **3** |

→ 전체의 **60%** 가 완료, **24%** 가 진행 또는 점검 단계

### 변경요청(CR) 현황 (총 **53건**)

| 항목 | 값 |
|------|:----:|
| 전체 CR 건수 | **53건** |
| 총 FP(기능점수) | **80 FP** |
| 총 공수(예상 시간) | **177.5 시간** |

## 5. 기대효과

| 효과 | 설명 |
|------|------|
| ✅ **업무 투명성 향상** | 관리자가 매일 1분만 확인해도 전체 진행상황 파악 가능 |
| ✅ **실시간 반영** | 인덱스만 수정하면 보드에 자동 반영 — 문서 작업과 현황판이 분리되지 않음 |
| ✅ **변경요청 통합 관리** | 계획서와 CR을 같은 화면에서 전환하며 확인 → 생산성 향상 |
| ✅ **표준 컴포넌트화** | 칸반보드를 표준 개발 지침으로 문서화하여, **신규 웹시스템에도 즉시 동일 패턴 적용 가능** |
| ✅ **개발 비용 절감** | 다음 프로젝트에서는 이 지침만 따라 만들면 되므로 설계·개발 시간 대폭 단축 |

## 6. 향후 계획

- 지속적 기능 개선 (예: 드래그 앤 드롭 상태 변경, 통계 차트 추가)
- 타 프로젝트 적용 시 사례 축적 및 지침 업데이트
