## 1. 배경 및 목적

`wordcloud_project/plans/2026/` 계획서와 `.clinerules/docs/cr` CR 보고서를 전수 분석하여, 간트차트의 **CR 연결선(`cr_links`)** 과 **선행 의존 화살표(`deps`)** 를 생성할 수 있도록 `_index.md`의 `관련 CR`(5열)·`선행`(6열) 컬럼 값을 백필한다.

생성 조건(소스 `plans_routes.py`):
- `cr_links` ← plan의 `관련 CR` 컬럼에 **실존하는** `REQ-XXXX-NNN` 이 채워져야 함 (`:1002-1005`).
- `deps` ← plan의 `선행` 컬럼에 **실존하는** plan 좌표(`DD_NN` 또는 `YYYY/MM/DD_NN`)가 채워져야 함 (`:989-995`). 해석 실패 시 `dep_warnings`(미해결)만 표시, 간선은 안 그어짐.

## 2. 현황 실측 (코드/데이터 확인 완료)

- **인덱스 스키마 격차**: `04/_index.md`, `06/_index.md`는 **4컬럼**(계획서/작업요약/상태/작성일)만 보유 → `관련 CR`/`선행`/`에픽` 컬럼 자체가 없어 71개 행이 링크 보관 불가. `07/_index.md`만 7컬럼.
- **파서 견고성**: `TABLE_RE`(`:237-240`)는 `^\|…\|…\|(상태)|\d{4}-\d{2}-\d{2}\|`까지만 앵커 → 뒤 컬럼은 무시. 추가 컬럼은 `full_line.split('|')` 후 `len(cells)>N` 가드(`:336-338`)로 안전. 07이 이미 7컬럼이고 정상 동작 = 실증됨.
- **소비처**: `관련 CR`/`선행`을 읽는 건 `plans_gantt`(간트)·`plans_lint`(린터)뿐. 칸반보드/CR현황/추이 뷰는 해당 필드를 참조하지 않음(§8 실측).
- **CR 말뭉치**: 고유 REQ ID **52건**(전체 파일 74개 중 `-r`·`-wordcloud` 변형 제외, `ls .clinerules/docs/cr/REQ-*.md | sed 's/.*(REQ-\d{4}-\d{3}).*/\1/' | sort -u | wc -l`=52 실측). 대다수 `REQ-2604-*`/`REQ-2605-*` 및 일부 `2606-*`는 **msys**(대시보드/히트맵/접속로그) 도메인으로 wordcloud 계획서와 무관.
- **결론**: 04·06 헤더 7컬럼 확장 + 값 기입만으로 간트 링크 생성 가능. 단, msys CR은 연결 대상 아님.

## 3. 설계 원칙

1. **정본은 `_index.md` 컬럼** — 메타블록은 선택 미러(`:48-52`).
2. **실존 좌표만** — dangling/unresolved는 간선 누락+린터 경고이므로, 확인된 REQ/plan 좌표만 기입.
3. **미확인 빈칸 금지(작성 게이트)** — 확정된 값만 기입, 모르는 건 `-`(확인된 없음). 본 계획은 전체 적용 방침.
4. **msys/wordcloud 분리** — wordcloud 도메인 CR만 연결, msys는 제외.
5. **검증은 lint + 3뷰 육안** — 코드 수정 없이 데이터만 바꾸므로 회귀는 뷰 확인으로 백스톱.

## 4. 구조/스키마

`_index.md` 헤더(7컬럼, `03.plan-mode.md §8`):

```markdown
| 계획서 | 작업 요약 | 상태 | 작성일 | 관련 CR | 선행 | 에픽 |
|--------|-----------|------|--------|---------|------|------|
```

- `관련 CR`: `REQ-\d{4}-\d{3}`, 복수는 콤마+공백. 빈칸=간선 없음, `-`=확인된 없음.
- `선행`: 동월 `DD_NN` 또는 타월 `YYYY/MM/DD_NN`. 동일 규칙.
- `에픽`: 영문 소문자 하이픈 슬러그.
- 데이터 행 확장 시 **매 행마다 3빈칸**(`| … | | | |`) 추가해 테이블 정합성 유지.
