## 1. 배경 및 목적

**핵심 발견 3가지 (코드 실측):**

1. **모델은 필드맹(field-blind)** — `finetune_sentiment.py:42` `load()`는 `(text, label)`만 뽑고, `:184` `tok(t)`로 순수 텍스트만 학습·추론한다. gold 데이터에 `field`(장점/단점)가 있지만 **모델엔 전달되지 않는다.**
2. **런타임 수집에 필드 개념이 없다** — `src/configs/mappings/last_mapping.json`은 CSV 한 컬럼("사용자 다면평가 결과")을 `evaluation_document` 단일 blob으로 매핑. `batch_processor.py:228` `_extract_rows_from_chunk`의 `mappings` 순회도 장점/단점을 분리하지 않는다.
3. **판정패킷 단계에서 필드가 유실** — `judgment_packet_service.py:191` `'field': ''`(문장별 미상). 규칙엔진(`perspective_service.py`)은 문장 내 단어로 "단점 맥락"을 *추론*할 뿐, 구조적 필드가 아니다.

결과: "전문성", "능력 습득" 같은 **무서술어 단편**에서 모델은 장점칸/단점칸을 모른 채 찍는다. 사용자 통찰([[project_field_signal_for_finetune]])대로 필드는 폴리세미 극성을 강하게 가르는 신호인데, 그 신호가 파이프라인에서 버려지고 있다. 이를 회수하면 그동안 "중립 보류"로 안전하게 도망친 단편들을 정확히 긍/부로 회수할 수 있다.

**목적:** 필드(장점/단점)를 감정모델의 입력 신호로 살려, 무서술어·다의 단편의 극성 정밀도를 올린다. **단 긍↔부 오분류 0 원칙([[project_sentiment_core_value]]) 불변** — 하드룰이 아니라 모델이 조건부 분포를 학습하게 한다.

## 2. 설계 결정 — 필드 제공 방식

### 2.1 채택: 헤더(데이터) + 매핑 UI(의미) 병행

> 🔒 **원데이터 비반입 원칙**: 평가 원데이터는 내부망 전용·PII 포함이라 Claude(외부망)로 가져오지 않는다([[project_dev_no_batch_csv_only]]). 필드 지정은 **전적으로 내부망의 매핑 UI에서 사용자가 수행**하며, 데이터는 밖으로 나가지 않는다. Claude가 만드는 것은 *메커니즘(UI 셀렉터+배선)*뿐이다.

| 맥락 | 제공 방식 |
|------|-----------|
| **(a) 프로덕션 배치**(19k, 내부망) | **컬럼 매핑 UI**에서 각 텍스트 컬럼에 *극성 필드 종류*(장점/단점/미지정)를 지정 → 파이프라인이 문장에 필드 부여. **원데이터는 내부망에만 존재.** |
| **(b) 학습 gold** (이미 가명·plans/·배포제외) | `emotion.jsonl`·`gold_8c_*`에 `field`가 이미 채워져 있음. Phase 1 A/B는 이 기존 gold만 사용, **새 데이터 불필요.** |

즉 **헤더가 값을 나르고, 매핑 UI가 "이 컬럼은 장점"이라는 의미를 태깅**한다. 서로를 대체하지 않고 보완한다.

### 2.1b 현행 파일 3종 → 단일 극성 태그로 통일

현재 원본 파일은 3형태로 들어온다. 모두 **컬럼별 극성 태그** 하나로 처리된다(별도 분기 불요):

| 파일 형태 | 매핑 방법 | 결과 field |
|-----------|-----------|-----------|
| ① 장점+단점 혼재(한 파일 2컬럼) | 장점 컬럼→`장점`, 단점 컬럼→`단점` 각각 태깅 | 문장이 온 컬럼따라 장점/단점 |
| ② 단점만 있는 파일 | 텍스트 컬럼 1개→`단점` 태깅 | 전 문장 `단점` |
| ③ 장점만 있는 파일 | 텍스트 컬럼 1개→`장점` 태깅 | 전 문장 `장점` |

②③처럼 파일 전체가 단일 극성이어도 문제없다 — 단점 파일에 긍정 내용("능력 습득")이 있어도 `단점`은 *뒤집는 라벨이 아니라 prior*이므로, 모델이 그 조건에서의 극성을 학습한다(§2.2 하드룰 기각과 동일 논리).

### 2.2 기각안 (근거)

- **인라인 마커** ("[장점]…[단점]…"을 한 셀에 혼재): 파싱 취약. 기각.
- **하드룰** ("단점→부정"): 사용자 자신의 r4 라벨이 반증 — 단점칸인데 긍정으로 판정한 실측:
  「타 전문기술 분야 능력 습득」(단점→긍정), 「해당분야에 대한 전문능력 습득」(단점→긍정), 「본인업무범위의 정확한 파악 및 숙지」(단점→긍정). 필드는 극성을 **뒤집는 스위치가 아니라 prior를 기울이는 신호**다. 하드룰은 이 반례들을 긍↔부로 오분류 → **최우선 금지선 위반**. 기각.

## 3. 구현 상세

### 3.1 Phase 1 — 학습 신호 주입 (빠른 실측·최소 변경)

- `finetune_sentiment.py`
  - `load(fn)`(:36): 각 행의 `r.get('field')`를 읽어, 있으면 텍스트를 **자연어 프리픽스**로 조립: `text = f"{field} 평가: {text}"` (예 "장점 평가: 능력 습득"). *특수토큰 `[장점]`은 tokenizer OOV로 `[UNK]` 처리될 위험이 있어* 자연어 프리픽스를 채택(호환 안전). 필드 없으면 원문 그대로.
  - 테스트셋 로드(`load(fn)` 공유)·`model_predict`(:204) 입력도 **동일 규약** 적용(정합).
  - 신규 인자 `--field-token {on,off}`(기본 off)로 A/B 토글. off면 기존 동작(회귀 가드).
- **A/B 실측**: `--field-token off` vs `on`으로 8c_hard 재측정. 주지표 ★긍↔부, 부지표 정확도·중립 재현율.
- 전제: 테스트/학습 gold의 `field`가 채워져 있을 것(현 `gold_8c_*`는 `field` 보유 확인). 빈 `field` 행은 무마커.

**A/B 실측 결과 (2026-07-07, after 파인튜닝 기준):**

| 테스트셋 | 지표 | off | on | Δ |
|---|---|---|---|---|
| **8c_hard** | **★긍↔부(주지표)** | **1**(부→긍) | **0** | **−1 ✅** |
| 8c_hard | 정확도 | 82.9% | 84.3% | +1.4pp |
| 8c_hard | 부 재현율 | 0.829 | 0.854 | +0.025 |
| 8c_hard | 긍 재현율 | 0.889 | 0.917 | +0.028 |
| 8c_hard | 중 재현율 | 0.794 | 0.794 | 0(훼손 없음) |
| baseline399 | ★긍↔부 | 0 | 0 | 0 유지 |
| baseline399 | 정확도 | 91.2% | 92.2% | +1.0pp |

→ **게이트 통과**: 8c_hard의 유일한 긍↔부 flip(부→긍 1) 소거, 두 셋 어디서도 긍↔부 악화 없음, 정확도 동반 상승. 부·긍 재현율이 함께 오르고 중립 재현율은 불변 = 필드 신호가 무서술어 단편을 *중립으로 도망치지 않고* 맞는 극성으로 회수. **Phase 2 진행.**

### 3.2 Phase 2 — 수집 단계 필드 캡처 (프로덕션 정합) 〔확정 설계 — 두 필드 방식〕

> **사용자 확정 설계**: 별도 셀렉터·자동감지·`field_polarity` dict 다 불필요. **메타데이터 구조에 `장점`·`단점` 문서 필드 2개를 정규 필드로 추가**하면 기존 매핑 UI가 그대로 컬럼을 붙인다. **둘 다 매핑=장단점 함께 있는 파일(케이스 ①), 하나만 매핑=단일 극성 파일(②③).** 매핑 자체가 극성 지정이라 추가 UI가 없다. (이전 `field_polarity` 예약키 안은 폐기.)

- **메타데이터 구조 확장**(`metadata_batch.js:defaultMetadataStructure`): `evaluation_document_strength`(장점)·`evaluation_document_weakness`(단점) 두 필드 추가(둘 다 optional). 기존 `evaluation_document`는 `required:false`로 완화.
- **필수 검증 개정**(`startBatchProcessing`): 문서 필드(일반/장점/단점) 중 **최소 하나 매핑** 강제. 미리보기도 일반→장점→단점 순 폴백.
- **추출**(`batch_processor.py:_extract_rows_from_chunk`): 모듈 상수 `POLARITY_DOCUMENT_FIELDS = {evaluation_document_strength:'장점', evaluation_document_weakness:'단점'}`. 매핑된 극성 필드마다 **별도 evaluation 레코드**로 방출 — 공통 메타 공유, `evaluation_document`=해당 컬럼값, `evaluation_document_field`=장점/단점. 미매핑이면 현행 단일 blob(field=''). 빈 셀은 레코드 생략.
- **문장 전파**(`judgment_packet_service.py:select_hard_sentences`): `ev.get('evaluation_document_field','')`를 item `field`로 세팅(기존 `''` 대체). 문서 단위 단일 극성이라 문서 내 전 문장이 상속.
- **하위호환**: `evaluation_document`(10개 소비처) 구조·의미 불변. `mappings.items()` 순회 타 지점(`perspective_service:1377`)은 이미 `isinstance(str)` 가드 → 안전.

### 3.3 Phase 3 — 런타임 감정분석 배선

- 감정분석 호출부(문장→극성)가 문장의 `field`를 함께 받아, Phase 1과 **동일 프리픽스**로 모델 추론. train/serve 정합 확정.
- 필드 미상(단일컬럼 레거시)은 무마커 → 기존 결과 불변.

## 6. 테스트/검증 계획

1. **Phase 1 A/B**(사용자 GPU 승인 후): `--field-token off/on` 각 1회, 8c_hard 정확도·★긍↔부 비교. off가 기존 수치 재현(회귀 가드)하는지 먼저 확인.
2. **단위**: `load()`가 field 유/무에서 프리픽스를 올바로 조립(빈 field=무마커)하는지.
3. **정합 테스트**: 학습 프리픽스 규약 == 추론 프리픽스 규약(같은 함수 경유) 단언.
4. **수동 왕복**(사용자): 장점/단점 2컬럼 CSV 업로드 → 매핑 UI 극성 지정 → 배치 → 판정패킷 `field`가 채워지는지 확인.

## 7. 리스크 및 제약

- **train/serve skew(최우선)**: 학습에 필드 넣고 추론에 안 넣으면 악화. Phase 1은 학습·추론 동일 함수 경유로 강제, 프로덕션은 Phase 3에서 배선 후에만 필드 프리픽스 활성.
- **긍↔부**: 하드룰 금지·모델 학습으로 조건부 분포 → 안전방향. 단, A/B에서 긍↔부 악화 시 즉시 롤백.
- **OOV 토큰**: 특수토큰 대신 자연어 프리픽스 사용으로 회피.
- **하위호환**: 단일컬럼·기존 배치는 필드 미지정 → 무마커, 기존 동작 불변.
- **원데이터 비반입**: 평가 원데이터(PII)는 내부망 전용. 필드 지정은 내부망 매핑 UI에서만 수행, Claude는 원데이터를 받지 않는다. Phase 1은 기존 가명 gold(plans/)만 사용.
- **서버/GPU**: 서버 무단 실행 금지, GPU 재학습은 사용자 승인 후. DN은 수동 왕복 실동작 검증 후(그 전 Pre-Done).
