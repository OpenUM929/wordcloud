## 1. 문제 (0623_02의 장점-only 검증 한계)

0623_02는 장점 데이터에서 긍↔부 0(0.6→94.5%)으로 보였으나, **장점엔 적대적 프레이밍이 없어 거짓 자신감**이었다.
`23_단점.csv` 전수 재현 결과:

- **부→긍(KoTE 부정우세 → override 긍정) = 11,039건**(`positive_rescue` 과구제). 핵심가치(긍↔부 0) 위반.
- 마커 격리(역량표지 7종 런타임 제거): 기존(HEAD) positive_rescue 버그 **10,855** + 0623_02가 새로 만든 **187**.
- 원인: `positive_rescue`가 긍정/역량 표지를 **단점 맥락**(개선 바람·요함/요망·보완요청·곤란)에서도 구제.
  기존 `has_constructive_need`('필요'/'요구됨')·`has_unnegated_deficiency`('소홀')가 **희망형·요함/요망·보완요청·어려움**을 못 잡음.
- → `batch_20260622`(긍정트레이트+결핍명사, wild-eagle) 와 동일 클래스.

## 2. 해결 (additive·시그니처 불변 — 부→긍만 감소)

`src/services/perspective_service.py` 신규 `has_improvement_request(sentence)` → `positive_rescue` 게이트에 `and not has_improvement_request(...)` 추가. 포착 프레이밍(trap 가드 포함):

| # | 프레이밍 | 포착 | trap 가드(긍→부 0 보호) |
|---|---------|------|------------------------|
| 1 | 개선 바람(희망형) | 했으면/하였으면/면 좋겠/였으면/면 합니/하길 바람 … | 다중자 매칭(오발동 낮음) |
| 2 | 요망 / 요함 | '요망'·'요함' | '중요함'·'필요함' substring 제외(앞글자 중/필) |
| 3 | 보완/개선 요청 | '보완'·'개선' + 요청동사(하면/해야/필요/요함/바람) | 직후 창 negation('없/않') 시 제외 → "보완점 없음" 보존 |
| 4 | 곤란 | '어려움'·'어렵' | 극복/없/헤쳐/해소/이겨 근접 시 제외 → "어려움 극복" 보존 |

- **`is_no_weakness_declaration` 혼합체크엔 넣지 않음**: 이 게이트는 후행 '없음'을 완전 negation-aware로 처리 못 해
  ("개선 및 보완필요점 없음") 약점-없음 선언을 부정으로 밀 수 있음 → 게이트 전용. 약점-없음 중립화는 기존 로직에 위임.
- **제외(trap이라 의도적 미포착, 파서/필드 트랙)**: 과잉어('너무/과한'="너무 우수함"=장점 칭찬)·주어의존('별로'="보완점 별로 없음"↔"열의 별로 없음")·맨 역량 명사구("타부서 협조"=장점란 긍정/단점란 부정).

## 4. 잔여 / 범위 밖 (파서·필드맥락·파인튜닝 트랙)

- **맨 역량 명사구**("다른 사람과의 협력"·"타부서 협조"·"업무열의 및 윤리의식"): 단점란=부정, 장점란=긍정 → **필드/주어 맥락** 필요(렉시컬 불가). 잔여 부→긍의 최대 버킷.

- **substring trap**('무관심'⊂"업무관심"): 토크나이저 후속.
