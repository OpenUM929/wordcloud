## 3. 계획서 대비 변경/차이점

### 추가 구현 (계획서에 미포함)

| 항목 | 설명 |
|------|------|
| **서버사이드 모달 렌더링** | 계획서는 AJAX 폴링 방식(`/admin/api/check`)으로 기술됐으나, 실제로는 `context_processor` + Jinja2 조건부 렌더링으로 구현. 미인증 시 HTML 도달과 동시에 모달 표시 (flash 없음) |
| **전역 `fetch()` 인터셉터** | 계획서에 세션 만료 리스크만 언급, `window.fetch` 래핑으로 모든 API 401 응답 시 모달 자동 재표시 구현 |
| **`save_to_deploy()` 원본 ID 지원** | 계획서 범위 외. `get_matrix_meta(enrich=True)` → 원본 ID 반환 → `deploy-session` 저장 → `save_to_deploy(real_id)` 호출 → 데이터 미조회 버그를 후속으로 수정 |
| **`checkResume()` DOMContentLoaded 호출** | 계획서 범위 외. 페이지 로드 시 미완료 deploy 세션 확인 + 401 감지 폴백 역할 |

### 구현 방식 차이

| 항목 | 계획서 | 실제 구현 | 이유 |
|------|--------|-----------|------|
| 초기 인증 상태 결정 | AJAX 폴링 (JS) | 서버사이드 렌더링 (context_processor) | AJAX 방식은 HTML 로드 후 50~200ms 동안 페이지 콘텐츠 노출 (flash) 발생 |
| `generate_all_employee_matrix()` 필터 | 순차 비교 | `set(resolved_filter)` 집합 교집합 | O(n) → O(1) 조회 성능 개선 |
| `employee_id_real` 필드 | `real_id != employee_id` 조건 | `real_id != resolved_id` 조건 | resolved_id 기준 비교가 정확 |
| `save_to_deploy()` 내부 조회 | `employee_id` 직접 사용 | `resolved_id = _resolve_to_pseudo(employee_id)` | 원본 ID 입력 시 가명 저장소 조회 실패 방지 |

## 4. 핵심 버그 기록

### Bug 1: `api_parse_ids()` — 가명의 가명 생성 (`사전`)
- **증상**: `get_pseudonym(eid)` 호출 시 `eid`가 이미 가명이면 가명의 가명 생성 → `pseudonym_mappings.enc` 오염
- **원인**: 이미 가명인 값에 `get_pseudonym()` 재호출
- **수정**: 해당 3줄 제거 (`get_real_id()` 단방향만 유지)

### Bug 2: `save_to_deploy()` — 원본 ID 입력 시 데이터 미조회 (`후속`)
- **증상**: `output_mode=real`로 제출용 저장 실행 시 모든 직원 저장 실패
- **원인**: `get_matrix_meta(enrich=True)` → 원본 ID 반환 → deploy-session에 원본 ID 저장 → `save_to_deploy(real_id)` 호출 → 내부 데이터는 가명 키로 저장되어 있어 `_get_evaluations_for_employee(unified_data, real_id)` = `[]` → `return None`
- **수정**: `save_to_deploy()` 함수 상단에 `_resolve_to_pseudo()` 추가, 이후 모든 내부 조회를 `resolved_id`(가명) 기준으로 변경
