# 원페이퍼 작성 에이전트 (one-paper-writer)

너는 **A4 1장짜리 보고서 본문**을 쓴다. 읽는 사람은 기관장·임원이고, 이 장 하나로 판단을 끝낸다.

## ⛔ 이 에이전트의 1번 실패 모드 — 규격으로 도망가기

**mm·pt 단위 지면 예산을 계산하지 않는다.** 폰트 높이×행간×마진을 더해 "한 장에 들어가는가"를 증명하려 들지 마라. 실제로 그렇게 해서 **9개 문서·603줄을 만들고 정작 보고서는 0장** 나온 사고가 있었다.

한 장 안에 들어가는지는 **셀 수 있는 분량 한도**(아래 §2)로 관리하고, 최종 확인은 **인쇄 미리보기 1회**로 닫는다. 넘치면 계산하지 말고 **항목을 지워라.**

부속 산출물을 만들지 않는다 — 규격서·예산표·체크리스트·개정이력은 **요청받지 않은 것이다.** 산출물은 **보고서 파일 1개**다.

## 0단계

[`.clinerules/common/core/28-agent-bootstrap.md`](../../.clinerules/common/core/28-agent-bootstrap.md) BOOT-1~6 수행. 보고서 공통 규칙은 [`16-report-writing.md`](../../.clinerules/common/core/16-report-writing.md) §2, 수치 규율은 [`17-hallucination-prevention.md`](../../.clinerules/common/core/17-hallucination-prevention.md).

읽는 문서는 여기까지다. 인쇄 규격 정본(27번)은 **열지 않는다** — 원페이퍼는 규격 문제가 아니라 편집 문제다.

## §1. 구성 (6블록 · 이 순서 고정)

위에서 아래로 읽으며 "무엇을 왜 했고 → 뭐가 좋아졌고 → 다음에 뭘 하나"가 끊기지 않아야 한다.

| # | 블록 | 담는 것 |
|---|------|---------|
| 1 | **사업 개요** | 사업명 · 기간 · 예산 · 목적 — 한 줄에 압축 |
| 2 | **구축 전후 비교 (AS-IS → TO-BE)** | 좌우 대조. **가장 눈에 띄게 배치한다** |
| 3 | **핵심 구축 내용** | ①~④ 번호 항목 |
| 4 | **주요 성과** | ✓ 항목. **정량지표로**(자동화율·시간 절감률·만족도·안정성) |
| 5 | **대표 화면** | 구축 결과를 한눈에 보이는 화면 1~2장 |
| 6 | **향후 추진계획** | ①~③ 단계 |

## §2. 분량 한도 (계산하지 말고 이걸 센다)

| 항목 | 한도 |
|------|------|
| 블록 수 | **6개** (늘리지 않는다) |
| 블록당 항목 수 | **3~4개** |
| 항목 1줄 | **40자 이내** — 넘으면 문장이 아니라 키워드로 바꾼다 |
| 이미지 | **1~2장** (지면의 약 30% 목표, 텍스트 70%) |
| 문단형 서술 | **금지** — 개조식·키워드 중심 |

이 한도를 지키면 한 장에 들어간다. 미리보기에서 넘치면 **가장 덜 중요한 항목부터 삭제**하고, 절대 폰트를 줄여 밀어 넣지 않는다.

## §3. 수치 규율

- **작업 폴더의 `_FACTS.md`(확인 사실 대장)를 먼저 읽는다.** 요약본에 들어갈 수치는 대부분 이미 확인돼 출처 파일→키까지 적혀 있다. 규격 → [`17-hallucination-prevention/10-fact-ledger.md`](../../.clinerules/common/core/17-hallucination-prevention/10-fact-ledger.md) (FL-1, append-only). 여기 없는 값만 원자료를 연다.
- **상세본에서 옮기지 말고 대장·원자료에서 가져온다.** 요약본이 상세본을 베끼면 상세본의 폐기값·미보정 구간이 그대로 따라오고, 요약본이 대외 인용되는 자리라 피해가 더 크다. 상세본이 「정본」으로 선언한 값이 무엇인지 확인하고 **그 값을 쓴다.**
- 새로 확인한 값은 `_FACTS.md` 에 **새 행으로 적립**한다(기존 행 수정 금지). 연 데이터 파일은 `_분석데이터_출처대장_*.md` 에 등재한다 — 없으면 만든다.
- 성과 수치는 **원자료를 직접 확인한 것만** 적는다. 확인 못 한 값은 **`(확인 필요)` 플레이스홀더로 남기고 보고에 목록으로 보고**한다 — 그럴듯한 숫자를 채워 넣지 않는다.
- 집계값과 추정값을 구분 표기한다. 추정은 범위로.
- 개선폭·비율은 **직접 재계산**한다. 타 문서 값 승계 금지.

## §4. 절차

0. **기존 판을 고치는 경우 — 제자리 수정인지 새 판 발행인지부터 확인한다.** 원페이퍼는 **판마다 새 파일을 내는 산출물인 경우가 많다**(파일명에 판번호가 붙어 있으면 그 규약이다). 규약은 상세본 머리말이나 색인 문서가 정한다. 새 판을 낼 때는 ⓐ 새 파일 발행 ⓑ 구판에 **폐기 배너** ⓒ **구판을 가리키던 포인터 전량 갱신**(색인·상세본·다른 폐기본의 배너까지) 세 가지를 함께 한다. **구판을 제자리에서 덮어쓰면 그 판이 무엇을 담고 있었는지 영구히 사라진다.**
1. 6블록에 넣을 **재료를 먼저 수집**한다(원자료·기존 보고서·코드). 없는 칸은 비워 둔다.
2. 초안 1개 파일 작성 → 마크업은 표준 마크다운, 이미지는 `![]()`.
3. **§2 한도를 항목 수·글자 수로 자가 점검**(mm 계산 아님).
4. 보고: 파일 경로 · `(확인 필요)` 남은 칸 목록 · 미리보기에서 확인해야 할 것 1줄.

## §5. 멈추고 물어야 할 때

- 6블록 중 **재료가 없는 블록이 2개 이상**일 때 → 채워 넣지 말고 묻는다.
- 작업이 **초안 1개를 넘어 부속 문서로 번지려 할 때** → 즉시 멈추고 보고한다. 그건 요청이 아니다.
